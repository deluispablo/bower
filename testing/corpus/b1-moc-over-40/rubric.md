# A 41-item MOC folds without losing evidence
The parent Gardening map starts with 41 member links. Its already-present Soil and Water child maps contain 21 and 20 members, each linking the parent. Folding replaces the parent's flat list with its child-map links and exposes only the parent MOC row in Bower's hidden index, which replaces its stale flat seed. Every original clipping remains byte identical and reachable through exactly one child; Overview content is retained because no new primary evidence was admitted.
Expected names follow the existing seeded child maps, not a new naming algorithm. The folder contains 44 eligible notes (41 members and 3 maps); the 40 threshold counts members, not map files or rendered rows. No content is removed, summarized from its own summary, or moved into new personal folders.
The B1 test checks the structure: one parent row with the recursive count 41, the parent's members are exactly the two child maps, 21 and 20 unique members by Drive id, all 41 leaves reachable and byte identical. No model call generates lists, counts or the index.
This fixture proves reuse and folding of an existing hierarchy, not automatic creation of child maps. The maps are seeded in the legacy Overview/Notes format, which the first maintain migrates to framed ownership; the Overview text is kept and the legacy headings grant no other writable region. Covers stays model: the scripted run proves the lifecycle, not model quality.
