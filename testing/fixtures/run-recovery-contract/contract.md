## One representation and hash rule

Use immutable UTF-8 JSON records outside the journal: declarations in `.bower/piles/`, run manifests/checkpoints/reports in `.bower/runs/<runId>/`, dispositions in `.bower/piles/`. Resolve every actual `.bower` and namespace parent by scoped IDs/names, including duplicate folders; never use disambiguated visible paths as identity. Existing journal, runner JSONv1, note grammars and public RunWire are unchanged.

`C(value)` is a precise canonical encoding for this contract: recursively sort object keys by ascending UTF-16 code-unit order; retain array order; serialize strings with JSON.stringify escaping, preserving Unicode, CR/LF and whitespace with no normalization; reject unpaired surrogates; use only nonnegative safe integer numbers in these new records; encode integers in decimal with no exponent; prohibit undefined, NaN, infinities, -0, duplicate JSON keys and unknown object fields; emit no insignificant whitespace or trailing newline. `H(value)` is lower-case SHA-256 of UTF-8 `C(value)`. Raw text content hashes are SHA-256 of the specified UTF-8 string bytes, **not C(string)**. Blob hashes mean exact original Blob bytes, not decoded text, names or provider metadata. These rules fit existing platform crypto; no new dependency is justified. Fixture hashes are authoring checksums, not runtime evidence.

An immutable record's digest is H(the complete record), used in its filename and references; it contains no self-hash. Filename names are `declaration-<declarationId>-<hash>.json`, `manifest-<hash>.json`, `checkpoint-<revision>-<hash>.json`, `report-<hash>.json`, `disposition-<hash>.json`. References use logical ID plus digest where specified, not a guessed Drive ID. Identical canonical copies collapse to one identity; differing canonical bodies with the same logical declaration ID, run ID, revision/previous chain or disposition intent are a conflict, even if filenames differ. A matching digest is an integrity check, never a permission grant. Candidate discovery of malformed/unsupported/ambiguous opt-in data refuses safely without modifying originals.

## Exact proposed types

The following is the normative TypeScript shape. All objects are closed at runtime; every property is required unless `?` appears. Null differs from omission. Type aliases named `Hash`, `Id`, `Time`, `Path`, `Text`, `Version`, `FileKind`, `ErrorCode`, `RunReport` have the precise guards below. This code block is documentation, not an executable module.

```ts
type Hash = string; // exactly 64 lower-case hexadecimal characters
type Id = string;   // 1..128 ASCII letters/digits/_/-; logical IDs, not Drive IDs
type DriveId = string; // nonempty opaque string, <=1024 UTF-8 bytes, no controls
type Time = number; // nonnegative safe integer epoch milliseconds
type Text = string; // valid Unicode, no implicit trimming/normalization
type Path = string; // relative, no empty/. /.. components, backslash or controls
type FileKind = 'note'|'pdf'|'image'|'link'|'doc'|'sheet'|'audio'|'other';
type ErrorCode = 'offline'|'not-found'|'conflict'|'auth'|'unknown';
type Scope = { rootId: DriveId };
type DeclarationRef = { declarationId: Id; sha256: Hash };
type Content = { encoding: 'utf8'|'blob'; size: number; sha256: Hash };
type SeenFile = {
  fileId: DriveId; name: Text; parents: DriveId[]; folder: boolean;
  modifiedTime: Text; // valid RFC3339; observation, never an atomic-write promise
};
type VerifiedContent = Content & {
  provenance: 'fake-stored'|'adapter-read'; observedModifiedTime: Text;
};
type ContextDeclaration = { kind: 'absent' } | {
  kind: 'text'; memberKey: Id; originalText: Text; content: Content;
};
type Anchor = { kind: 'loose'; inboxId: DriveId } | {
  kind: 'folder'; inboxId: DriveId; name: Text; createKey: Id;
};
type Member = { memberKey: Id; name: Text; kind: FileKind;
  origin: Text|null; content: Content };
type Declaration = {
  v: 1; kind: 'pile-declaration'; scope: Scope; declarationId: Id; pileId: Id;
  createdAt: Time; anchor: Anchor; members: Member[]; context: ContextDeclaration;
};
type Binding = { memberKey: Id; file: SeenFile; content: VerifiedContent };
type Observation =
  | { memberKey: Id; state: 'missing' }
  | { memberKey: Id; state: 'unverified'; file: SeenFile }
  | { memberKey: Id; state: 'conflict'; fileIds: DriveId[] }
  | { memberKey: Id; state: 'verified'; binding: Binding };
// Observation is derived I/O input, not a persisted ready flag.
type CapturedContext = { kind: 'absent' } | {
  kind: 'text'; memberKey: Id|null; file: SeenFile; text: Text;
  content: VerifiedContent;
};
type CapturedPile = {
  pileId: Id;
  source: { kind: 'declared'; ref: DeclarationRef } | { kind: 'observed' };
  anchor: SeenFile|null; memberKeys: (Id|null)[];
  childFileIds: DriveId[]; context: CapturedContext;
};
type CapturedMember = { pileId: Id; memberKey: Id|null;
  file: SeenFile; content: VerifiedContent };
type CapturedJournal = { recordId: Text; sha256: Hash; fileIds: DriveId[] };
type Capture = { piles: CapturedPile[]; members: CapturedMember[];
  journal: CapturedJournal[]; places: { file: SeenFile; path: Path }[] };
type Target = { fileId: DriveId } | { createdBy: Hash };
type Properties = { by?: 'bower'; bowerNew?: '1'|null;
  asAdded?: Text|null; origin?: Text|null; kind?: Text|null;
  pile?: Id|null; bowerItem?: Id|null; bowerDeclaration?: Id|null };
type Effect =
  | { kind: 'move'; before: SeenFile; parent: Target; name: Text;
      properties: Properties }
  | { kind: 'create-folder'; parent: Target; name: Text; createKey: Id }
  | { kind: 'create-text'; parent: Target; name: Text; createKey: Id;
      text: Text; content: Content; purpose: 'generated'|'runner-json' }
  | { kind: 'write-runner-json'; before: SeenFile; beforeContent: VerifiedContent;
      path: '.bower/questions.json'|'.bower/requests.json'|'.bower/hashes.json';
      text: Text; content: Content }
  | { kind: 'bin'; before: SeenFile; capturedChildIds: DriveId[] };
type Operation = { operationId: Hash; ordinal: number; dependsOn: Hash[];
  effect: Effect };
// Uses the existing RunReport type exactly (five arrays; optional counts/requests).
type ReportContribution = { requires: Hash[];
  when: 'applied'|'rejected'; value: RunReport };
type Manifest = {
  v: 1; kind: 'run-manifest'; scope: Scope; runId: Id; requestId: Id;
  runScope: 'all'|'instructions'; allowWeb: boolean; requestedAt: Time;
  captureId: Hash; capture: Capture; operations: Operation[];
  reportPlan: ReportContribution[];
};
type Failure = { code: ErrorCode; message: Text };
type EffectEvidence = {
  file: SeenFile; trashed: boolean;
  content: VerifiedContent|null;
  provenance: 'fake-stored'|'adapter-read';
};
type Outcome =
  | { operationId: Hash; state: 'not-dispatched' }
  | { operationId: Hash; state: 'before-effect-refused'; failure: Failure }
  | { operationId: Hash; state: 'possible-effect'; dispatchId: Id }
  | { operationId: Hash; state: 'applied'; evidence: EffectEvidence }
  | { operationId: Hash; state: 'rejected'; failure: Failure };
type ReportState = { state: 'not-ready' } | {
  state: 'pending'; reportHash: Hash; body: ReportRecord;
} | { state: 'published'; reportHash: Hash };
type Checkpoint = {
  v: 1; kind: 'run-checkpoint'; scope: Scope; runId: Id; manifestHash: Hash;
  revision: number; previous: Hash|null; attemptId: Id; epoch: number;
  phase: 'queued'|'reading'|'writing'|'saving'|'done'|'failed'; phaseAt: Time;
  outcomes: Outcome[]; report: ReportState; retainedPileIds: Id[];
};
type ReportRecord = {
  v: 1; kind: 'run-report'; scope: Scope; runId: Id; captureId: Hash;
  manifestHash: Hash; report: RunReport;
};
type Disposition = {
  v: 1; kind: 'pile-disposition'; scope: Scope; pileId: Id;
  declaration: DeclarationRef|null; memberKeys: Id[];
  action: 'consumed'|'removed';
  authority: { kind: 'run'; runId: Id; reportHash: Hash }
    | { kind: 'person-bin'; intentId: Id };
  operations: { operationId: Hash; evidence: EffectEvidence }[];
};
type Record = Declaration|Manifest|Checkpoint|ReportRecord|Disposition;
```

This finite effect list covers this filing/report foundation; it is not the whole C04–C13 semantic proposal vocabulary. `create-text` does not grant arbitrary writes: generated purpose requires a separately validated generated-document destination/ownership proposal; runner-json purpose accepts only supported existing runner JSON at its verified system parent. New grammar-owned note splices/revisions/Undo need their separately assigned semantic operation contracts, not a free-form command added here. All existing second-brain capabilities stay required. No hard delete, overwrite of user-owned sections, fake binary update or new Worker/public phase is authorized.

## Runtime guards and identities (normative alongside types)

1. Parse strict JSON with duplicate-key refusal before canonical hashing. Reject unsupported v/kind, all unknown fields, invalid Unicode, unsafe integer sizes/counts/revisions/ordinals/times, invalid enum or nested record. Path rule is components separated by `/`, excluding empty, `.`, `..`; no backslash/control. Names are one nonempty component, not paths. Arrays that represent identities have no duplicates. CapturedJournal.recordId preserves the existing opaque JournalRecord id (including punctuation); validate nonempty/control-free bounded text rather than the new logical-Id character grammar. Legacy identity syntax is not narrowed. `parents` is a nonempty set for captured/effect files under scope, root ancestry is independently checked. Times are observations; sequence/authority comes from checkpoints, not sorting wall clocks. Failure messages are nonempty safe one-sentence UI copy; fixed diagnostics contain IDs/reasons, never record text/token/URL query secrets.
2. A declared pile has unique memberKeys, distinct from its context key and folder createKey. Content sizes are safe integers. Context is utf8 and its size/hash must equal exact originalText bytes. Loose layout requires exactly one member, context absent, verified actual Inbox parent and no invented file ID/folder. Folder layout requires at least one member or a nonempty original context; text-empty context with files is valid and requires its actual empty context file. Context absent means no expected context file. Creation time does not authorize ownership.
3. `declarationId`, `pileId`, `memberKey`, `createKey`, `requestId`, `runId`, `attemptId` are minted once by the appropriate trusted adapter, persist before use and never derive from names/times alone. Existing `bowerItem` stores memberKey; `pile` stores pileId; proposed `bowerDeclaration` stores declarationId as opt-in only. Lookup declarationId plus scoped canonical hash. Conflicting copies block; unknown/missing referenced declarations never fall back to external.
4. Initial member create intent digest = H({declaration: DeclarationRef, memberKey, parent: actual verified parent ID, name, content: declared Content}). For a folder anchor, same rule uses folder createKey and null content. Persist declaration and its validated intended parent/key before create; a confirmed record is checked against all scoped copies. Before-effect refusal preserves the same identity/body/authority; possible-effect create must reconcile, not repeat. Reconcile folder before children. A key reused with different bytes/place is conflict. Real first-publication uniqueness/unknown-create verification depends on R4; P2's controlled service serialization is explicitly bounded.
5. Derived readiness: every declared member has exactly one matching verified effect in the correct root/actual parent; every required context exists. Duplicate candidates, wrong scope, wrong hashes, unavailable proof, missing or unverified members block. Positive progress, filename, size alone, returned metadata or appProperties hash never substitutes for verified bytes. `fake-stored` means actual stored bytes independently inspected through the fake adapter, not expected labels. `adapter-read` requires an accepted read capability/version binding; current decoded readText can verify utf8 only, not arbitrary original binary bytes. No unimplemented provenance is silently upgraded. Observations and bindings are not permanent authority after a source changes.
6. On capture, declared references resolve all original expected identities but captured members/context hold current actual file IDs/versions/content evidence. Do not repeat original inventory in every checkpoint. Context may be edited: capture exact current text/version/hash, not stale originalText; current context bytes must independently equal the captured text content digest/size and version, while the declaration context digest still equals originalText; absence and present-empty differ. Edited context is not grounds to overwrite it from declaration. Original file bytes must match expected member content; context is the explicit mutable exception. Unmarked external/legacy piles use `source:observed`, null memberKeys, current actual membership and extraction fallback; no historical expected set is invented. Unsupported opt-in refuses. Scope instructions captures no Inbox piles and uses actual validated journal/rules references. Capture does not depend on app preparation.
7. `captureId` = H({scope: Manifest.scope, runScope: Manifest.runScope, capture: Manifest.capture}). Operations are fixed in manifest before effects; ordinals are consecutive from zero. `operationId` = H({runId, captureId, ordinal, effect}). `createdBy` and dependsOn resolve only earlier operations in this manifest; an actual file ID is bound by applied evidence, never a guessed placeholder. Reuse same IDs/manifest/capture on retry/reopen; changed intent needs a new explicit admission. Same requestId with different manifest is conflict. No operation can add later piles/children into capture. Dispatched effects require successful independent current ownership/content or name/place checks; observed modifiedTime is not CAS. Bin of a parent also requires fresh complete child IDs to be within the captured set; uncaptured child prevents Bin and retains parent/context. Losing a parent does not retire a declaration.
8. Every checkpoint contains exactly one outcome per fixed operation in ordinal order. `not-dispatched` → `possible-effect` is committed **before** issuing an effect. A trusted adapter that proves no dispatch/effect occurred may instead publish `before-effect-refused`; an HTTP error by itself does not prove that. Possible-effect transitions only to independently reconciled applied/rejected, or remains possible; absence alone permits no blind retry. Proven before-effect refusal may retry the same operation after current authority/preconditions check; changed source rejects or remains unresolved. Applied/rejected never regress or change evidence. Applied evidence must match actual effect, target scope, content for creates/writes, actual name/place for move, actual Bin state for Bin. An unrelated preexisting lookalike does not prove this operation applied. If provenance/uniqueness is unavailable, retain unresolved state.
9. Manifest reportPlan contains all authored wording, path/name/kind/to/note/question/counter/request contributions **before effects**. Each contribution requires one or more existing operationIds and is included exactly when all its requirements have the specified final state. No base ungrounded success rows. Fixed order is reportPlan order; concatenate five arrays and requests; sum optional counts from included contributions, keeping omission when never supplied. Question IDs must be unique across included contributions; conflicting duplicates refuse before effects. Each filed/created/updated/question/request/count success is independently tied by validator to appropriate effects (including journal archive/request result records as applicable), not just arbitrary op labels. An operation rejected after a partial dependency must not manufacture a success row. Mixed/unresolved dependencies yield a retained partial checkpoint; if no exact durable contribution exists, refuse report completion instead of regenerating text/model answers. Canonical report identity is H(the whole ReportRecord); runId/captureId/manifestHash bind it to precisely this run.
10. A pending report can be reconstructed after its first checkpoint fails **only because the entire reportPlan and all resolved effects/evidence are already durable**, or reconciled from previously durable intent and real effects. Reconstruct identical canonical ReportRecord, without another filing/model call. If evidence or any necessary wording is missing, saving/unknown remains discoverable and the entry stays open. Never assert the current runner already does this.
11. Checkpoint revision zero has previous null; subsequent records increment by one and previous equals the committed head digest. Scope/run/manifest never change. Same revision/previous with conflicting content blocks rather than selecting newest modifiedTime. Identical copies may acknowledge an unknown create reply only after verifying exact record contents and authoritative expected head. Complete previous chain and manifest are required; corrupt/unsupported referenced record means refusal without mutation. Uncommitted orphan immutable records are not silently selected as head; reconcile against the same service-owned expected publication before advancing.
12. `done` requires all operations applied/rejected, report published and independently resolved by matching digest/body, every consumed disposition verifiable, no unresolved result/publication; retained rejected piles are listed honestly. Pending publication maps to existing `saving`, no finishedAt. `failed` is allowed only when no possibly applied effect remains and no missing result evidence is discarded; effects with pending report remain saving/recoverable. New terminal completion does not follow a legacy reportless file. Old public fields derive from the service's committed head; no new enum silently enters RunWire.
13. Consumed disposition refers to the matching published same-run report and all relevant applied operations/captured member keys, with actual verified final effects. Removed disposition requires current authenticated explicit person Bin intent, actual per-member/container Bin evidence and preservation of original context/recovery record. It has no run/report requirement and is not inferred from a missing parent. Member key sets must equal the declaration/capture's affected full non-null key set; external observed inputs carry no fabricated member keys and their effect fileIds must equal the captured IDs; partial dispositions retain remaining rows. No premature disposition before result evidence. Disposition is immutable; only confirmed evidence makes it effective. A restored original contradicting old Bin evidence is retained visibly for explicit recovery, not erased/recertified by the old removal. Full Undo/restoration operation contract remains unimplemented and required under C13.

## Trusted scope and one claim/checkpoint mechanism

| Identity | Durable source / relation | Provider identity |
| --- | --- | --- |
| declarationId / pileId | Minted once; immutable declaration logical identity and canonical digest | Neither is a Drive file/folder ID. |
| memberKey / anchor createKey | Minted before initial create; reused as agreed appProperties keys; declaration preserves expected payload | Actual file/folder ID is absent before creation; bind only a uniquely verified effect. |
| captureId | Digest of trusted-scope/runScope/current verified capture, including declaration references and destination places | Captured IDs/versions are actual observations, not predicted IDs or CAS. |

One service-owned control row per authenticated binding/root carries requestId→manifestHash, active run, committed manifest/head, current attempt/epoch/expiry and monotonic status revision. Exact proposed control type:

```ts
type Control = {
  runId: Id; requestId: Id; scope: Scope; manifestHash: Hash; head: Hash;
  statusRevision: number;
  claim: null | { attemptId: Id; epoch: number; expiresAt: Time };

```

This row is operational metadata, not a second Drive mutation engine or a new public HTTP payload. P2 implements its compare/advance/claim/effect-boundary serialization through **one controlled shared fake service store**, owned independently of client lifetimes; the clock and scheduler are injected. Drive content stays on the shared fake Drive. Accept admission only after immutable manifest plus initial checkpoint and service row are durably confirmed in the simulated store; failing/unknown admission leaves discoverable pending intent, never successful acceptance. Duplication by requestId returns the same admitted run; changed intent refuses.

Only the service dispatches a runner under an authenticated unexpired claim. A returning authorized client may request recovery, never self-claim or execute from a manifest. Service validates current binding/root, committed head, expected statusRevision and all unresolved dispatches before issuing a monotonically greater epoch. At the controlled fake mutation boundary it serializes authority-check with the permitted mutation; expiry/revocation/stale attempt blocks effects and callbacks. An outstanding possible effect must be reconciled or proven quiescent before takeover; no clock-based assumption that an in-flight provider call disappeared. Publish an immutable checkpoint, verify all copies, then atomically compare/advance the control head; no Drive file overwrites are used as locks. Unknown checkpoint create/head response is reconciled by digest/current control head, not a second logical revision or choosing a different branch.

P2 must actually test this shared persistence and scheduler in O4; current per-page FakeWorker/pretend snapshots do not implement it. P3 chooses/proves its minimal operational coordination primitive separately under measured R3 evidence. A real service claim cannot fence already-dispatched direct Drive writes by itself. Without actual provider-safe preconditions/unique effect reconciliation/quiescence, the same unresolved operation remains blocked. This contract confers no Drive exactly-once/CAS/raw-byte guarantee and does not adopt the R1 remedy.

## Publication and report barrier

1. App confirms immutable declaration and correct actual Inbox/root/anchor before uploads. Reconcile verified complete members and current context; consumer refuses partial pile. The declaration persists even when member bytes require D02 reselection.
2. Service captures only the verified ready set, builds fixed plan/report contributions, confirms immutable Manifest + initial Checkpoint + control admission before acknowledgement. Later input is excluded. All source IDs/names/places/content evidence needed for recovery are in the capture/intent or referenced immutable declaration/journal, not a page closure.
3. For each operation, publish possible-effect intent checkpoint and advance the single authoritative head before dispatch. After response/reconciliation, publish evidence and advance head. Never skip unresolved predecessors or replay already applied operations. Parent Bin cannot swallow an uncaptured child.
4. From resolved evidence and durable reportPlan build the exact ReportRecord. Persist a pending checkpoint containing it, advance head, then create/reconcile `report-<hash>.json`; **first pending-checkpoint failure** recovers from the already durable plan/evidence. Report-create lost reply reconciles exact canonical bytes; no second effect. Confirm persisted matching report before creating a published checkpoint.
5. Publish required consumed dispositions only from confirmed same-run report/evidence; retry their immutable publication by exact identity, without effects. Then commit done checkpoint/control status. Legacy `.bower/last-run.json` is a compatibility view, written with the read modifiedTime only after the authoritative report/checkpoint are recoverable. If this terminal view write fails, remain saving and retry the same report/view from another client; no new manifest/run/refiling. A response lost after view effect is reconciled by exact same-run body. Only after the view is confirmed may the service expose done to existing LiveRuns; preserve its existing report-reading contract. A stale or wrong-run latest view cannot replace the archived same-run report; upgraded hydration can locate that report only through the trusted current run/control reference. This requires a later explicit consumer assignment, no change now.
6. Terminal publication failure logs a BowerError and retains discoverable saving/control head/pending body. Sign-out disposes that client and local person data but neither deletes another scope's records nor lets unauthorized runners continue. Re-authenticated service may recover the same run subject to current authority; revoked credentials show refusal/pending, no silent effect. Scheduler durability and closed-origin browser acceptance are O4 tests, not this document's claim.
