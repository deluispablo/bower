# Changelog

Operator-facing changes, newest first. Entries under **Operator action required** need a manual step on redeploy.

## Unreleased

- Rules version 24 (#962): the rulebook is cut into sections with `<!-- load: … -->` markers, so a run can be handed only the parts it needs; the agent no longer opens the rulebook, `Rules.md`, `About-Me.md` or `log.md`, and searches `index.md` with Grep instead of reading it whole. Every new `index.md` row carries one to five tags and a short description (`- [[<path>]] · <Type> · <#tag #tag> · <description> · <origin>`), and the tags live in a new `## Tags` section at the end of `index.md`; Bower adds a tag there only when none fits, and the `tag` kind of suggestion is gone. Bower transcribes a scanned PDF's text copy itself, writes a text copy the first time it answers about a filed PDF that has none, and writes only judgement lines to `log.md` (`Rule added/changed`, `Correction`, `Proposal`, `Context`, `Applied rule`). The weekly check completes up to 50 old rows with tags and descriptions. Old rows stay valid and the app reads both formats. The runner side follows in #966 and #967; until then the runner still hands the agent the whole rulebook. Deploy the Worker (`bash scripts/deploy-api.sh`) so new folders start with version 24; each owner then applies it from **Settings → Advanced → "Update Bower's rules"**.
- **Operator action required.** v6 (every screen redrawn, per-folder statuses): deploy the Worker (`bash scripts/deploy-api.sh`; its folder template now carries rulebook v23), then rerun `bash scripts/deploy.sh` for the runner's new `run.sh` and the app; each owner then applies rulebook v23 from **Settings → Advanced → "Update Bower's rules"**, after the runner is updated. No new secret, variable or Worker route. What people see: the phone's second tab is **Folders**, also a drawer swiped in from the left edge; one text box with a round mic button everywhere you type, with a crossed-out mic and one line when dictation is off or blocked; one list row, file icon, page header and ⋯ menu on every screen; a note named after its own folder is that folder's page and is not listed or counted (unless it says `by: person`); a folder's header counts what is directly in it, a subfolder's row or card and a pinned folder count everything inside; Compare's status select offers the folder's own list, with a legacy value kept as the last option; the Bower item is a speech bubble and the sidebar has no bird. The demo is local only (`pnpm -C app build:demo`), with the `bower:demo:slow` and `bower:demo:fail` session switches for the loading and error states. See "Deploy order for the v6 update" in `docs/runbook.md`.
- Statuses chosen per folder (#921): Bower writes a status list for each folder that compares notes (in the folder's hub note, `statuses:`), and the runner removes a list it cannot use and says so in the run's summary; the kind's list stays the fallback. Rerun `scripts/deploy.sh` for the new `run.sh`; each user gets the new rulebook (version 23) from **Settings → Advanced → "Update Bower's rules"**. See "Rulebook v23: statuses chosen per folder" in `docs/runbook.md`.
- License: Bower is now Fair Source, under the Functional Source License 1.1, MIT Future License (`FSL-1.1-MIT`), instead of MIT. Running your own instance, changing it and sharing it stay allowed; offering it as a competing product or service is not. Each version becomes MIT two years after its release. Versions published before 30 September 2026 remain MIT.
- **Operator action required.** v5 (runs, piles, uploads, recovery, Bower on screen): deploy the Worker (`bash scripts/deploy-api.sh`), then the runner (rerun `bash scripts/deploy.sh`), then let the app build from `main`; each owner then applies rulebook v21 and v22 in one tap from **Settings → Advanced → "Update Bower's rules"**, after the runner is updated. The default `DAILY_RUN_LIMIT` is now 100 and `DEFAULT_MAX_TURNS` 60 (an instance's own values are kept). One tidy-up costs about 6 KV writes; the free tier's 1,000 a day is shared by everyone on the instance. Details: the runbook's "Deploy order for the v5 update".
- Apply a rule to what is already filed (#372): the job a rule's menu sends now makes Bower go through the folders the rule names and move or rename what it covers, logging each move as a `Correction:` line. Rerun `scripts/deploy.sh` for the new `prompts/ingest.md`; each user gets the new rulebook (version 12) from **Settings → Advanced → "Update Bower's rules"**.
- `Rules.md` has a shape Bower and the app share (#376): topic headings, one dated rule per bullet, and a paused rule struck through, which Bower never applies. Rerun `scripts/deploy.sh` for the new `prompts/ingest.md`; each user gets the new rulebook (version 11) from **Settings → Advanced → "Update Bower's rules"**.
- Context notes (#370): what you type in Add's **What is this?** box now applies to that batch: the files it names are filed and get what it asks (a table, a summary, a translation), and a "from now on" sentence in it becomes a rule. Rerun `scripts/deploy.sh` for the new `prompts/ingest.md`; each user gets the new rulebook (version 10) from **Settings → Advanced → "Update Bower's rules"**.
- A note from Bower (#371): every note Bower writes because it was asked (an answer, a job's result, what a rule asks for) starts with **Bower's note** (only ✅ ⚠️ ❌ bullets), **Why** and **What Bower used**, with each source's origin. Rerun `scripts/deploy.sh` for the new `prompts/ingest.md`; each user gets the new rulebook (version 9) from **Settings → Advanced → "Update Bower's rules"**.
- Sensible names for originals (#369): a file whose name says nothing (`IMG_4471.jpg`) is filed under a name from its content, such as `Arlington Road, window sign.jpg` (at most 60 characters, never a person's name); a meaningful name is kept. `index.md` lists filed files with their type and origin. Rerun `scripts/deploy.sh` for the new `prompts/ingest.md`; each user gets the new rulebook (version 8) from **Settings → Advanced → "Update Bower's rules"**.
- Bower only files, by default (#368): a tidy-up moves each original into its project, area or resource folder as it is, with a line in the folder's hub note, a row in `index.md` and a `Filed:` line in `log.md`, and writes no summary note unless one is asked for (a web clip or saved link, an instruction note, a rule in `Rules.md`, a converted document). The run report gains a `Filed: <n> files` line. Rerun `scripts/deploy.sh` so the instance repo gets the new `prompts/ingest.md` and `run.sh`; each user gets the new rulebook (version 7) from **Settings → Advanced → "Update Bower's rules"**. See "What a tidy-up does with each file" in `docs/runbook.md`.
- A note's **More** menu has a new **This was misfiled** row (#200): it opens Tell Bower prefilled with the note's path, asking where it should go. The resulting move request appends a `Correction:` line to `log.md` instead of a plain one, and the same correction happening twice files a proposal in **Health** suggesting notes like it be filed there directly. Existing folders pick up the reworded rulebook (version 6) from Settings → Advanced → "Update Bower's rules".
- Bower's suggestions (#199): the agent now files what it would like you to decide (a new rule, a workflow, a domain tag) in `Answers/Bower - Proposals.md` instead of only in `log.md`, and **Health** lists the open ones with **Accept** (the rule goes into `Rules.md`) and **Dismiss**; the weekly check removes decided ones after 30 days. Rerun `scripts/deploy.sh` so the instance repo gets the new `prompts/ingest.md` and `prompts/lint.md`; each user then gets the new rulebook (version 5) from **Settings → Advanced → "Update Bower's rules"**. See "Bower's suggestions" in `docs/runbook.md`.
- Bower's own rulebook now spells out what it may learn on its own (preferences, recurring kinds of document, vocabulary) and what it may never record (credentials, identifiers, health or financial details found inside a note, anything about a third party); the weekly health check now also flags a contradiction, an over-long `Rules.md` (past 200 lines) or a forbidden content kind it finds there, and the report's frontmatter carries the `notes`, `findings` and `brokenLinks` counts the Health screen reads (#201, #173). Existing folders pick up the reworded rulebook from Settings → Advanced → "Update Bower's rules".
- **Operator action required.** Runner jobs no longer hold `BOWER_API_KEY` (#259): the Worker mints a ticket per run and per Bower folder and sends it with the dispatch, and the runner routes accept only that ticket, for that folder, until the run ends. The weekly health check is now started by a small `dispatch` job (the only one with `BOWER_API_KEY`) through the new `POST /runner/lint/dispatch`, one workflow run per folder, and `Ingest` lost its manual **Run workflow**. Rerun `scripts/deploy.sh` so the instance repo gets the new workflows and `run.sh`; until it has them, every run fails with `HTTP 401` unless the Worker var `RUNNER_ACCEPT_LEGACY_KEY=1` is set for the transition (`docs/runbook.md`, "Upgrading to run tickets").
- The agent now accepts an instruction note only when it is directly in `0-Inbox/` with the app's own file name and frontmatter (`tags: [instruction]`, `via: app`); a `Bower*.md` clipped anywhere else, such as `Clippings/`, is filed as ordinary content instead of obeyed. Rerun `scripts/deploy.sh` so the instance repo gets the new `prompts/ingest.md`.
- The instance repo's `BOWER_MAX_TURNS` variable is now actually passed to `run.sh` from both workflows (it was documented but had no effect); rerun `scripts/deploy.sh` so the instance repo gets the updated workflows.
- The runner's agent no longer has web access by default: `WebSearch` and `WebFetch` are denied (with `curl` and `wget`), so a clipped page cannot make it send notes anywhere, and the prompts treat note contents as data, never instructions. An instance that needs the web sets the repository variable `BOWER_ALLOW_WEB=1`; rerun `scripts/deploy.sh` so the instance repo gets the new `run.sh`, prompts and workflows.
- A note appended to or edited from the app while a run is in progress is no longer overwritten when the run finishes: the runner now uploads only the files the agent added or changed. Rerun `scripts/deploy.sh` so the instance repo gets the new `run.sh`.
- The weekly health check no longer shows up as a Process run in the app: the runner reports it with `kind: "lint"`, the Worker keeps it apart (`lintrun:<id>`), and the push says "Health check ready" (or "Health check failed") and opens **Health** instead of counting inbox files. Rerun `scripts/deploy.sh` so the instance repo gets the new `run.sh`; until then a lint still reports as an ingest.
- Notes can be edited from the app: **Edit**, next to a note's title, opens a plain-text editor with a small formatting toolbar. If the note changed elsewhere since the editor opened, Save asks whether to keep your version, take the other one, or open both (not offered for `CLAUDE.md`, `index.md`, `log.md` or `_*.md` folder notes).
- An email-in inbox is documented as an optional, not-built extension an operator could add on their own instance: `docs/extensions/email-in.md`.
- Weekly health check: the instance repo's `lint.yml` now runs every Sunday at 06:17 UTC over every user's Bower folder (listed with the new `GET /runner/vaults`), and the app shows the result under **Health**, with a badge when a new one arrives. Rerun `scripts/deploy.sh` (or `scripts/new-instance.sh`) to copy the new workflow into the instance repo; see "Weekly health check" in `docs/runbook.md`.
- A file added to `0-Inbox/` or `Clippings/` while a run is in progress is no longer sent to the Drive Trash when the run finishes; the runner now deletes only the originals it processed.
- Semantic search spike (#51, see git history): recommends embedding notes locally in the runner; implementation decision still open.
- Onboarding's "I already have a folder" step can open the Google Picker to choose a folder visually, instead of pasting a link; the paste-a-link form still works and is the fallback when `VITE_GOOGLE_API_KEY` isn't set or the Picker fails to load. Optional: see "Google OAuth client" in `docs/runbook.md`.
- Sign-out and delete-account now clear the device: cached notes and images (IndexedDB), the `bower-api` and share caches, the Drive token, and per-user preferences (theme kept) — so a shared device shows nothing of the previous user afterwards.
- Notes can be added to from the app: **Add to this note**, under a note, appends a paragraph to its end in Drive (not offered for `CLAUDE.md`, `index.md`, `log.md` or `_*.md` folder notes).
- `docs/runbook.md` is now one document covering deploy from zero, day-to-day operations (rotating keys, quotas, logs, costs), pausing and tearing down an instance, and adding or removing a user; see it for the full deploy walkthrough.
- **Operator action required:** `scripts/deploy.sh` deploys everything in one run (instance repo, KV, Worker, secrets, app on Pages) and reruns cleanly; `scripts/new-instance.sh` creates or updates the private instance repo. Your real `[vars]`, KV id and custom domain now live in the git-ignored `api/wrangler.local.toml`: if you edited `api/wrangler.toml`, move those values there (or delete your edits and let the script ask) and put `api/wrangler.toml` back to its placeholders. See "Deploy" in `docs/runbook.md`.
- Notes show attachments: embedded images inline (cached on the device), links to PDFs and other files open in Google Drive in a new tab, and `![[Other note]]` shows that note inline once.
- `docs/privacy.md` is written and served by the app at `/privacy`; give Google that URL (`<APP_ORIGIN>/privacy`) on the OAuth consent screen. See "Deploy" in `docs/runbook.md`.
- **Operator action required:** the app and the Worker must be served from one registrable domain (for example `app.example.com` and `api.example.com`); the default `*.pages.dev` and `*.workers.dev` hostnames do not carry the session cookie. See `docs/security.md`.
- Deploying the API: `pnpm -C api deploy` and `pnpm -C api secrets` (or `scripts/deploy-api.sh`) create the KV namespace, walk through the secrets, and deploy the Worker. See "Deploy" in `docs/runbook.md`.
