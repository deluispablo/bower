## Evidence boundaries and the local standard

The existing standard is recorded before-image recovery, not a model guessing how to reverse text. `src/data/contracts/note-edit.ts:843` cites ARIES (Mohan et al., ACM TODS 17(1), 1992, https://dl.acm.org/doi/10.1145/128765.128770). `undoEdit` checks the current content against the manifest's resulting size and hash before returning the before-image; missing evidence is `unsupported`, changed bytes are `person-edited` (`:847–851`). This citation comes from local code; no external source was fetched. Reuse the existing manifest, note-edit, mutation fences and planner. These helpers are evidence of recovery primitives, not a whole-run product entry point.

The accepted C05 review added exact question counts, typed subjects and two-run edits; these are now present (`runner/src/corpus.ts:31–49`, `:92–95`, `runner/test/corpus-run.ts:153–176`, `:362–404`). Do not re-propose those gaps. The later driver also supports answer presses and request replay (`harness/corpus/README.md:72` onwards). Neither `CorpusBetween` nor `CorpusPress` has an undo action (`runner/src/corpus.ts:31–43`). The driver maps undo admission to instructions but sends the original scope in a `bower-tidy` event (`runner/test/corpus-run.ts:244–259`). Production runner dispatch accepts only `all` and `instructions` (`runner/src/main.ts:318–325`). Therefore `scope: undo` is a corpus vocabulary value, not demonstrated product undo support. A words-only request saying “Undo” is not authorization for the model to author an inverse.

Both old C13 cases are `covers: model`, with post-run folder snapshots and no recorded manifest or checkpoint (`harness/corpus/c13-undo-whole-run/case.json:5`, `harness/corpus/c13-undo-protects-edit/case.json:5`; their folder inventories). Whole-run checks returned source and absent note; edited-note checks a retained sentence and one set-aside (`harness/corpus/c13-undo-whole-run/expected.json:2–14`, `harness/corpus/c13-undo-protects-edit/expected.json:2–19`). Their rubrics require recoverable Bin and honest partial recovery; the edited-note rubric explicitly calls report names provisional (`harness/corpus/c13-undo-protects-edit/rubric.md:2`). They are expectations, not successful undo executions.

The scorer checks path presence/absence, starting-byte equality, note substrings, Timeline entries/counts, changed-note links and report list counts (`runner/src/corpus.ts:260–340`). The driver adds protected byte ranges, Drive properties and per-press scoring (`runner/test/corpus-run.ts:333–404`). It excludes folders and Bin from the returned content map (`runner/test/corpus-run.ts:49–50`, `:280–299`). Neither file absence nor `setAside: 1` proves a recoverable Bin, same-id restoration, the reason shown, or a completed undo. `linksResolve` ignores unchanged notes and does not prove dependency-safe recovery (`runner/src/corpus.ts:299–304`). All three new cases remain `covers: model`: deterministic forward objects are drafted, but there is no verified end-to-end undo driver. Passing the requested tests will not execute their proposed undo outcomes (`runner/test/corpus.test.ts:37–40`).
