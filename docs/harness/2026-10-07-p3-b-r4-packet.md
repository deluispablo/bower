## Part B: a resumable upload interrupted by a reload

1. In a new folder `U` inside `D`, start a resumable upload ([manage uploads, resumable](https://developers.google.com/workspace/drive/api/guides/manage-uploads#resumable)) of a deterministic 10 MiB binary, where byte `i` is `i % 251`, MIME `application/octet-stream`.
2. Send one 8 MiB chunk. Keep the session URI only in `sessionStorage` (`r4_session`), never logged. Reload the page.
3. The fresh page sends the status query (`PUT`, `Content-Range: bytes */10485760`, empty body) and resumes from the offset the server reports (`Range` header).
4. Check, by listing `U` and a `files.get`: exactly one file, `size` 10485760, and an `md5Checksum` equal to the md5 you computed locally.
5. **Withheld final reply:** a second 10 MiB upload in `U`. Send its last chunk but treat its reply as lost: record it, then drop it. Reconcile with a status query before any new create, and record what Drive says (a 200/201 with the file, or a 308 with the range). Then show exactly one file in `U` for that upload.

Bounds: 80 requests, 40 MiB uploaded, 15 minutes.
