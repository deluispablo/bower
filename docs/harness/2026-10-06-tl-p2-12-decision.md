# Technical-lead decision TL-P2-2026-10-06-12

Lead: Claude `Planificador`. This answers M7 from the readiness delta review and amends TL-P2-09. Adopted revision stays `2026-10-05-contracts-2`.

## A filed member the person later binned still counts as "arrived and left"

TL-P2-09 required the member to be "not in the Bin". That is too strict. Bower filed the member, and putting it in the Bin was the person's later decision. It must not block the rest of the pile.

The new rule: a declared member whose file carries the same `bowerItem` counts as arrived and gone from the pile when two things are true:

- its parent is outside the pile folder;
- it has the declared size and sha256.

This holds whether or not that file is in the Bin.

- Bower never restores that member, never files it again, and never lists it as "Didn't arrive".
- If the key matches but the hash differs, the file is still a `conflict` observation.
- A member put in the Bin while still inside the pile folder is a different case: the person removed it from the pile. That case follows the existing removal flow, not this rule.
- This is still a readiness fact. It never writes a disposition.
