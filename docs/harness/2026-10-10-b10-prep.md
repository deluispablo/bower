## Proposed mechanism contract — lead recommendations only

There are three different texts, with one home each: the **original** is primary and
immutable; the **preparation synopsis** is C15/B10's bounded derived model input; the
**B2 summary** is the ≤200-character metadata line on a new Bower note. The companion
body is the existing authored source-note route, not a fourth summary service. Never
serialize a person note just because its text was long. Cache preparation rather than
mutating the source or putting a synopsis in a person's front matter.

Recommend a deterministic trigger of **more than 3,000 whitespace-separated words in
complete extraction**, before planner display cuts. At exactly 3,000, retain the ordinary
path. Partial extraction is flagged independently, regardless of prefix word count:
unknown total length cannot certify “short/complete”. C15 may expand safely; if the
budget cannot supply the rest, describe only the read part and retain partial coverage.
Never download/read all pages merely to count words. Current unavailability/OCR limits
stay; B10 does not attempt another reader. Exact trigger remains Q2, not a worker ruling.

The current **12,000-character perThing limit is planner display**, and today also
limits PDF extraction. Case 2 cannot be satisfied by that prefix: its needed tail is
beyond it. Recommend that C15/B10 may feed **up to 48,000 source characters to the one
isolated synopsis call**, charged against the same run source-character pool, only
after complete extraction is known. This is a proposed preparation-input extension,
**not an existing entitlement or a second 48,000-character allowance**. Keep planner
perThing at 12,000; charge the later synopsis display as well. If raw evidence plus
framing/other source consumption cannot fit, use the partial policy. Q3 requires the
lead to approve this boundary; no test pretends current bounded() supplies the tail.

Recommend a **≤1,000-word synopsis and ≤4,000 characters including limitation text**,
whichever is reached first, sharing C15/B1's character pool. Headings/bound facts/coverage
are included, not free overhead. Preserve parties, dates, amounts, conditions, contradictions
and useful changes; do not pad a document with advice or unrelated links. If essential
facts cannot fit, say the synopsis is limited and keep the original available; no automatic
recursive summary-of-summary or map/reduce extraction of unseen pages. Haiku is the
TL-P4-38 direction; model id/default/call-size configuration uses the existing claude
configuration/isolation home after corpus comparison, not a guessed new API or API-key
batch service. Do not unilaterally lower a red's numeric bounds or select a new model id.

C15's chosen prepared-artifact envelope is the sole cache. Recommend its extraction
identity plus an optional synopsis component holding its own version, configuration,
coverage and source-bound evidence refs; **no B10-only cache file/registry**. Include
account/folder, source id/current hash, extractor version/configuration, extraction coverage,
synopsis version/model/prompt/language and any request-dependent focus in validity. Prefer
a request-independent source synopsis so a focused request does not reuse the wrong omission.
A stale/foreign component is a miss/refusal per C15's ruled policy; derive from current
admitted bytes only, never from an old synopsis. B12's 30-day whole-request result cache
is a different capability and does not make a stale source synopsis valid for 30 days.
Partial cache may serve the exact compatible partial view, never a complete promise.

Synopsis model calls receive source data/coverage only, no note content/web tools and
no consequential operations. Proposed facts carry original source refs; script checks
admission, version, span/page membership and every figure against original supplied
text. A free-form paraphrase is not mechanically proven true by a valid ref: model
quality review checks entailment and preserved conditions. The execution validator
consumes source-backed evidence for grounding, never treats the generated synopsis
as new numeric truth or trusted person input. B1's frozen targets stay fixed.

Preflight one shared reservation before model dispatch. Charges include validation
reads/downloads, full/partial extraction text, synopsis and planner input/output,
invalid-reply retries, context exchanges, effect operations, cache writes/fences,
checkpoint/reconcile traffic, maintenance and report. Keep B1's 20% reserve; a summary
step cannot spend the final planner/effect/report allowance. Cache hits save extraction
or model work, not source-validation/execution cost. Account for parallel elapsed time
without summing overlapping durations. If no safe complete read/synopsis fits, use the
honest partial path where fit is clear or C15's existing unclear-result policy; do not
invent silent truncation, more question rounds, an extra quota allowance or continuation.

Frozen accepted terminal content uses the existing planner→manifest→effects→barrier.
Cache content needs C15's explicit runner-artifact admission and ordinary modifiedTime/
write-once recovery. After the plan is persisted, lost cache/create/move responses resume
that plan, never re-extract or re-summarise. Before that point, a restarted attempt can
reprepare within the same accepted request budget; do not claim the current runtime
already persists those counters. A cache saving failure follows C15's agreed optional-
acceleration policy; it cannot fabricate “done” or lose the original. No after-run writer.
