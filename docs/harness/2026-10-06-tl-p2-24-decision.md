# Technical-lead decision TL-P2-2026-10-06-24: single-session S1 details

Lead: Claude `Planificador`. This answers the copy and design questions from `single-active-session` S1. It applies TL-P2-13 and TL-P2-14.

## a. Reusing existing sentences

- **"Bower is not ready yet."** for a write before the session has started: approved.
- **"Bower's server didn't answer. Try again."**: only when there was no answer at all, such as a network failure or a timeout. When the Worker answers with a refusal, say "Bower couldn't open here. Try again." Saying "didn't answer" after an answer would be untrue.

## b. Design: approved

These five choices are approved:

- **Expiry.** A place finds out it has lost the session when it sees another epoch inside `{active, epoch}`, without any change to that shape. It then blocks and releases.
- **Headers.** `x-bower-place` and `x-bower-epoch` go on `/process`, `POST /vault` and `DELETE /me`. Allowing these headers in CORS is recorded as a P3 obligation.
- **`WorkerApi.session` is optional, for compatibility.** Every fake and demo factory must provide it, because a client without it is not fenced. The fake Worker refuses those three calls from a place that does not hold the lease.
- **A blocked place** disposes of its status source and stops the upload queue.
- **Offline at start** means active but unconfirmed. Every write still checks the lease before it acts.

## c. Uploads held only in memory are not lost when the place is blocked

Being blocked does not close the page, so the queue keeps these uploads paused in memory. They are the uploads that have no copy on the device because storage failed. "Use here" in the same page sends them.

While any such upload exists, the block screen adds one sentence: "Some things you added here are only on this page. Use Bower here to send them."

Closing the page loses them, which is the risk the notices N1 and N2 already warn about. Uploads with a copy on the device resume as before.
