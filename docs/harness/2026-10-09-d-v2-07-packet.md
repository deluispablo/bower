### Channels and scope

1. **Two channels, each with one owner. No second idle loop.**
   - `engine.idle()` (engine.ts:796) is the one mind. `perch()` (:703-792) is the one pose script.
   - **Gaze channel:** the iris ix/iy, plus a small head offset. The mind always owns it. The offset is added after the act channel and never writes over it.
     - In **working poses** (read, write, carry, proud, land, alarm), gaze moves the iris only, with no head offset, so each pose's range test holds.
     - In **idle and wait**, the head offset is clamped to that pose's CSS head range (idle −12..7).
   - **Act channel:** head, tail, jaw, tuft and wing targets.
     - In working poses, the pose script owns it. These poses get gaze and the engine blink, and nothing else from the mind.
     - **idle and wait (TL-P4-25 addendum 3 (2)):** `perch()` hands them to the mind and keeps only their rest frames. Wait also holds its tuft at 8°. Both share the one act table below; wait adds the `look` act. Their acts replace the fixed CSS-era loop and use the CSS angles.
   - **Iris:** gaze overrides it whenever input is being followed. Otherwise wait's `look` act moves it.
2. **Mind options `{ sleeps, acts }`.**
   - Perched birds take `sleeps: true`. Layer birds (Add, Replay, TidyScene) and the landing take `sleeps: false`.
   - Layer birds get gaze, preen and startle only while perched between flights. They never get them during a flight, a carry (`B.carrying`) or a script step.
   - `acts: false` pauses the mind's act scheduling. It is a test seam.
3. **The run chip** (34 px, minor) keeps its still frame, with no blink and no engine. presence.ts is untouched.
4. **Sleep reuses the sleep pose's targets**, with no second sleep frame.
   - `apply()` reads one `asleep` flag in place of `pose === 'sleep'` (:940). The flag is set by the sleep pose, or by the mind after 60 s.
   - The mind sleeps only from idle or wait. Waking restores `B.girth`, and `setPose` clears `asleep`.
   - A bird in the sleep pose (Home.tsx:164, TidySheet.tsx:77) stays asleep on input: no gaze, no startle, and a tap does nothing.

### Acts (addendum 2 (3), (8))

The engine gains `act(name)`, which fires one named act. It is engine API, not only a test seam: d-v2-24's `react()` will use it. Each act's range is the value below plus 2°.

| Act | Weight | Motion |
| --- | --- | --- |
| snap | 40 | head to −12° or +7° (the CSS snaps; replaces `rand(-26,22)`, engine.ts:830) |
| flick | 20 | tail to −14°, then +4° |
| chirp | 12 | jaw to 14° |
| wing | 10 | wing target −10° for 0.22 s (replaces `wing.vel += 260`, :833) |
| preen | 8 | head 38→42→38°, twice in 0.9 s; iris down and back. It never sets `B.girth`. |
| pause | 10 | nothing |
| look (wait only) | in wait's draw | iris to −2.2, then +1 (wait's CSS iris loop) |

- The timer fires every 0.8–2 s and draws by weight. One draw in ten is a pause, so the timer runs every 0.8–2 s, not the act.
- Blink: every 1.6–5.2 s, with a double one time in four (the existing ranges, engine.ts:828, :873).
- The old random `turn()` (:834) goes. The behind-the-pointer turn with a hop after 0.5 s stays.
- No snap or preen while input is recent (2.5 s).
- **Fixture:** `pose-reference.fixture.ts` gains act entries with numbers: jaw 14 (chirp), wing −10 (wing), preen 38/42, and look (iris −2.2/+1). The idle/wait checks become per act.
- **`act(name)` vs the private `act(a: Action)`** (engine.ts:316, 9 callers): rename the private one, which is in scope.

### Input and gaze (addendum 2 (5))

- **API:** `look(p, source)` with source pointer, focus or touch; `nudge()`, which wakes the bird with a startle (tuft 18° for 0.6 s); and the existing `poke()`.
- **Listeners** live in useBirdEngine's look source. PoseBower has none of its own.
  - pointermove calls `look(point, 'pointer')`.
  - pointerdown or touch calls `look(point, 'touch')`, and the gaze holds for 2.5 s.
  - keydown and focusin call `look(rect of the focused control, 'focus')`.
- **Recency:** every input event marks it, `nudge()` included, and so does `look`, in engine time.
- **Focus:** the gaze stays on the focused control while focus stays there. The 2.5 s window only stops snaps and preens.
- **Sleep:** it comes 60 s of engine time after the last input event (or after mount, if there has been none), even while focus is held.

### Tap (addendum 1 (5), addendum 2 (4))

- **The perched box** gets `aria-hidden` and a pointerdown listener. The listener never calls preventDefault or stopPropagation. Bower is never focusable, and no key pokes it.
- **The engine gains `interrupt({ now: true })`.** It cuts the running act or loop cycle at the next frame, and the springs carry on from where they are. It keeps `B.carrying`, unlike `interrupt()` today (:321-324). The cut action's `end()` runs only that act's own cleanup. A tap therefore starts within 0.1 s, and the loop resumes after the poke.
- **A perched bird's carry is a pose,** so a tap cuts its cycle.
- **A layer bird in flight or carrying** is in a layer state. Its latest tap goes in one slot, never `S.queue`, and plays when the current action ends; it is never dropped. setPose or interrupt clears the slot. BowerLayer's existing `onClick` (Bower.tsx:323) follows the same rule through the one `poke()`. There is one queue.

### Still when asked

- **"Bower moves" off, or reduced motion:** the bird holds its pose, with no following and no sleep.
  - There is one home: `src/ui/media.ts` `useMedia` (TL-P4-25 addendum 3 (1)). Bower's `useMoves` calls `useMedia('(prefers-reduced-motion: reduce)')`, so flipping the query mid-render stops the engine.
  - Delete `prefersReducedMotion()` (prefs.ts:62). prefs.ts gets no new hook.
  - The flip test's matchMedia stub, which fires 'change', lives in Bower.test.tsx.
- **Hidden tab:** the engine clock does not advance, so a hidden tab does not count toward sleep. A tab shown again resumes with no startle.
