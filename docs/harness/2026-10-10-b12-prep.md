## Proposed contract for the lead, not a ruling

One optional maps execution arm carries a selector for an already script-bound request
and set, and bounded per-member results. Each result contains only the four operations
below, naming allowed target/destination ids. Script assigns request/set ids, provenance,
member ordering, op ids, digests and fences. The model cannot define a set, replace its
members, grant a write, invent runner paths or nominate an extra shared profile.

| Operation | Proposed admitted form / deterministic composition |
| --- | --- |
| move | `{kind:move,targetId,parentId}`; existing folder id from the bound neighbourhood. B6's normal create/reuse may declare a needed folder first, with its existing reserved-id dependency; no B12 hierarchy builder. |
| rename | `{kind:rename,targetId,name}`; recordable name, same extension; combine with move into one ordinary move effect. Fix required links through the existing link-rewrite, grouped by id. |
| property | `{kind:property,targetId,key,mode:set|union,value}`; B5 declared type/allowlist, finite bounded value. union only for raw lists, stable first-seen order, dedup and cap checked **after combination**. No formulas; B11 owns them. |
| tag | `{kind:tag,targetId,mode:add|remove,value}`; B7 canonical installed slug. Add may use B7's automatic growth effect before dependent edits, with the same run-wide caps; no tag proposal. Remove removes only the explicitly bound tag, never prose. |

Property/tag writes apply only to mutable compiled Bower note metadata. A person note
or immutable Source is unavailable for those writes; moving/renaming a supported file
changes no content except the separately admitted mechanical link consequence. A request
must explicitly authorize the destination/name/metadata operation; membership alone is
not authorization for any operation. App hard rules remain intact.

Planner order: resolve/classify the trusted request → freeze candidates and targets →
preflight aggregate cost / offer part if large → prepare only authorized tasks → validate
each output → combine by target id against one verified before-text → persist final
manifest → primary metadata edit → dependent move+rename → required combined link fixes →
settled request/result projection through maintain → ordinary barrier. Freeze worker output
in the final manifest; same-run application replay never calls the model again.
Required link dependencies and moved-note edit guards need Q3's contract; no speculative
ordering here claims the current guard accepts this sequence.

Conflicting scalars on one target are unavailable for that target, with contributing
members linked; unrelated targets may settle. List/tag caps apply to the combined result,
so overflow refuses the shared target whole. Missing worker output is an unavailable
member, not silent success. A deterministic already-satisfied operation can count done as
a validated no-op; it creates no updated row. A composite member is done only after all
its required operations and mechanical consequences are confirmed. Partial effects retain
individual outcomes; no rollback or new transaction engine is promised.

Large admission stores exact ordered ids and offered subset, plus immutable authority and
permission ceiling in the existing request/manifest state. No treats the offer as declined,
with no mapped write/run; yes starts the ordinary answer loop for the stored part only.
Technical continuation is limited to unfinished work **inside** that part, retains its
budget and uses current permission intersected with admission permission; it cannot
broaden web access. The request's unoffered remainder is not an automatic continuation.
Current Q1 inbox scope/rounds are unchanged for other subjects.

Widen **requests.json**, not a new queue or ledger, with optional active map descriptors
(frozen members/targets/actions, result-note id, budget, per-member settled receipts and
manifest references) and a compact 30-day recent-success projection. Current done rows
remain leniently readable; their last-20 display retention cannot evict active descriptors
or thirty-day skips. Only settled, verified outcomes update it. A checksum or display
result note alone never grants consent. Corrupt request state stops that request with a
logged BowerError; it cannot silently re-resolve/re-authorize it.

Recent key recommendation: root/account + canonical task/action/arguments + member/target
ids + evidence/result fingerprint; store completedAt and outcome proof. Match the actual
requested operation, not just a file id or company label, so a new rename/tag request is
not skipped for an unrelated older task. Verify matching postconditions/current evidence;
changed inputs, Undo and unsuccessful results cannot be skipped as completed. Expiry is
`now >= completedAt + 30 days`, UTC milliseconds, with an injected clock. Same-run recovery
still uses its manifest after expiry. Forget/About me lineage remains B4, not this cache.

The readable result note uses B6/B2 generated-note construction and note-edit for updates,
id-bound to the request, with links to original/final notes and grounded script counts.
One result note per approved request part, reused by its technical continuations; a new
“rest” request gets its own result note. Maintain combines its update with the request
projection, consuming B8's per-artifact outcomes and existing fences before the barrier.
No archive of this script projection, new report kind, hidden-file row or mutable source
body. For B11, an approved subset is labelled as a subset; existing whole-set views over
the bound remain unavailable until a complete view can be computed, never filled with a
200-of-201 total. The split is reused, not a second evaluator or a silent partial total.
