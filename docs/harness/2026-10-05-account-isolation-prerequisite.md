## Recommended bounded approach

Make account/folder lifetime an **internal local epoch**, distinct from request tickets and backend authority. Bind each operation and its file IDs, parent IDs, journal owner and pending bytes to the epoch/root it entered. Invalidate the epoch on sign-out, deletion, auth expiry and a new confirmed folder/session; clear visible old state before the new session is published. The same root after sign-in is a new epoch: it must not reactivate any pre-transition promise or queued action.

Prefer epoch-scoped vault/journal/run state behind stable source dispatch if this avoids scattered continuation checks. Equivalent in-place reset is acceptable only if every affected read, write, queue and publish path captures/checks the same epoch. Worker chooses the smaller maintainable internal implementation; neither choice changes Sources/Me/Worker wire/durable formats. Keep concrete LiveSources capabilities used by tests/integration (DriveVault refresh/flush/settled/lastRun, LiveRuns runningPiles/dispose) available; do not silently narrow them.

A cache refresh alone is insufficient. The current index ignores changed root (`drive-vault.ts:616`), and additional scoped maps retain note/text, Bin, uploads, sending and system-folder promises (`:70`–`:80`). Journal queues resolve owner repeatedly at execution time (`journal.ts:142`, `:177`, `:181`, `:266`). LiveRuns captures no session epoch; its generation changes only on admission/disposal. These retained continuations can cross a session boundary even after ordinary visible data is relisted.

## Lifecycle and interface constraints

1. **Session resolution and publication.** Guard pending `me`, current/root and createFolder responses with the epoch/promise identity. An old response must not make A's identity/folder usable after B was confirmed. Scope invalidation must precede session emission that remounts signed-in screens. Existing createFolder behavior should confirm its returned folder and reset the appropriate scope rather than merely launching unawaited refresh. During transition, block new person operations; successful sign-out/delete keeps existing device cleanup. If a lifecycle request fails, report it and allow a fresh legitimate session retry rather than restoring stale in-flight operations. Do not claim sign-out succeeded on failed provider logout.
2. **Signed-out access.** `session.current()` remains null. Cached tree/note/rules/request/person reads and mutation dispatch must not return A data or send Drive writes while signed out. Use a short auth BowerError for person vault access; run current may return the existing API's null, with empty locks and no old report, or a readable auth refusal. Harmless no-data/no-op calls need not manufacture auth errors. Stale operations use a session-changed conflict/unknown refusal, avoiding recursive watchAuth expiry storms.
3. **Stable subscriptions.** Preserve Sources identity and functioning subscriptions. If internal instances rotate, bridge current source events through stable listeners and detach old bridges. Replacing a field without reconnecting subscriptions is insufficient: useLoad subscribes only for its source/dependency lifetime. Old callbacks, progress, storage writes, cache insertions and emissions cannot publish into B. MarkSeen/dismissed/Undo closures need the same bound-scope check, even when they perform no Drive call.
4. **Reads and caches.** Check epoch before using cached state, after delayed listing/text/fullText/root responses and before return/publication. Old index/text promises cannot populate the fresh scope. New B reads use B root and identifiers. Root identity is an existing folder boundary, not a new stable-account-subject claim; invalidate on lifecycle transitions even when root strings match. Refresh within an unchanged active epoch still preserves its pending work and coalescing.
5. **Mutations.** Before each *new* I/O side effect, recheck the captured epoch and use its captured root/IDs; never resolve a fresh B root halfway through an A operation. Preserve existing modifiedTime/name/place checks. Old queued operations reject rather than being replayed under B. A mutation already dispatched may complete in A; this patch cannot cancel, roll back or prove provider authorization timing. Ignore stale visible result, prevent subsequent unrelated effects, and retain original-owner journal bookkeeping for observed applied effects.
6. **Run lifecycle.** Invalidate pending status/report hydration, run locks, reports, retired-ID/loading maps and foreground refresh scope. Guard returned/subscribed state and old timers/refresh continuations, not only status acceptance. Capture the epoch when start is requested, before it waits in `starts`; check after flush/piles and before process, and after replies/hydration. A queued A start cannot become B's process call. New B start/retry must not depend on an indefinitely pending old queue. Old promise finally handlers must not clear a fresh B loading/foreground/refresh promise; use epoch and promise identity. Do not cancel already-dispatched process work or invent backend attempt authority.
7. **Journal owner and persistence.** Capture owner/root once before queue admission, including lock namespace, sendWaiting/list/remove and post-effect record. Do not look up a new owner separately inside each delayed callback. On invalidation, refuse further remote sends/removals; retain all folder-keyed localStorage and volatile outboxes. Already observed A effects need A-keyed bookkeeping even if the remote journal send is now forbidden. A queued unsent request/rule must either already be retained in A's outbox or reject truthfully; it must not report success and disappear. Fresh B sends/reads must use only B's changes folder. Returning to A can flush A records through fresh active A work, never reactivate the old callback. Preserve content-match acknowledgement/dedupe.
8. **Volatile identity trap.** Journal memory is a WeakMap keyed by DriveApi identity (`journal.ts:78`). Creating a new scoped I/O proxy per epoch must not orphan A's volatile outbox when storage is blocked. Keep a stable underlying Drive identity for the memory store, or retain the existing store explicitly while replacing only scoped read/queue state. Do not copy records into B's key or erase other folder entries.
9. **Uploads and Undo.** Sign-out forgets device person state except journal outbox; no adopted policy requires retaining undispatched upload blobs through sign-out. Drop/suspend visibility and release unsent person bytes under that existing rule; do not add durable upload recovery or automatic resume policy. Already-issued transport may remain alive until settlement. Epoch exit must occur **before** progress/emit/cache updates, next item dispatch and the `sendAll` removed-pile cleanup at `drive-vault.ts:718`–`:725`: clearing uploads alone otherwise makes the late response trigger trash with the new credentials. Do not trash/rename/untrash late A results to compensate for session invalidation. User Bin/remove within an unchanged epoch retains its established late-upload cleanup/Undo behavior. Incomplete-pile/readiness and reload policy remain separate open work; do not label them solved.

An in-flight A write whose successful result arrives after the transition is an observed A effect. Preserve its original-owner journal line locally without sending it to B; stale UI success/navigation must not publish. An unknown/lost reply remains an unknown outcome under existing recovery limits, not evidence that nothing happened. Root-bound bookkeeping is not forced rollback or exactly-once provider proof.

## Decision and proof limits

No public/schema/product decision is needed for this current-contract isolation fix. Technical lead approval would become necessary only if the worker proposes a new account identity wire field, serialized upload/checkpoint format, or changes what survives sign-out. Recommend none of those here. Existing sign-out forgetting rule governs unsent blobs; folder-keyed durable/volatile journal exception remains mandatory. Owner upload-reload/offline-reading questions and stable backend subject/attempt authority stay unresolved and are not inferred from this packet.

Original coordinator account-switch observations at e15 and143 establish the concrete defect; they do not prove all proposed races. The matrix above is planned assertion coverage, not passed tests.
