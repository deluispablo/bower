# Technical-lead decision TL-P4-13: rulings on the coordinator's C05 findings

**Source:** [the coordinator's findings](2026-10-08-p4-c05-findings.md), written at the owner's request so that defects are solved at the root.

## 1. Defects that repeat: prevent them up front

**Adopted.** Every packet carries a fixed checklist, which goes into `WORKER.md` and the coordinator's packet template:
- **Every Bin, move or write passes what it read** (bytes, modifiedTime or md5). A test changes the file between the read and the act.
- **Match by id,** never by name or substring.
- **Every new sentence in the app is backed by a test of the behaviour it promises.** No copy promises anything unbuilt.
- **The red reproduces the live evidence,** with its numbers and its shape. A missing hook or a mock does not count as red.

**Entries that bin, merge or move start on `bower-escalated`.** Of the reopened entries, two had data-loss bugs, and both were on this path.

## 2. Harness friction

- **The worker card lists the exact verify test names.** `verify-names-precheck` (`bower-mechanical`) makes `check-harness` reject, before merge, a verify name that exists in no test file.
- **Reviewers never start a server or run e2e.** They read the diff, run the unit and contract tests, and judge against the packet. E2e belongs to the coordinator's gates.
- **A full `e2e:fake` runs before merging any change** to corpus, demo or fake fixtures.
- **`--known-green`** stays, but each use is recorded in the entry with a reason.

## 3. Product and quality decisions

1. **"Write it", a yes to the per-note question.** Build it, consistent with the owner's choice (A).
   - `state-yes-writes` (`bower-escalated`): the yes starts a scoped run that writes Bower's update into that Current state and sets the mark.
   - The person's previous text is kept in the manifest, so undo restores it.
   - Until it is built, the honest "not yet" copy stays.
2. **Home ignores `usePiles().error`.** This breaks a hard rule, so `home-errors-shown` is fixed now: one short sentence, a retry, and the details to `console.error`.
3. **Home's refresh clears the cache in the middle of a read.** `home-cache-stable` fixes it now: a refresh never invalidates a read already in flight.
   - Target: Home's full read on the fake within 2 s, with a call golden. The live figure is measured at the next deploy.
   - The Tidy up count shows only once readiness is known (or "checking"), so it never drops after being shown.
4. **The corpus contains invented facts.** `corpus-grounded-scorer` (`bower-mechanical`) makes the scorer check that every number in `expected.json` appears in the case's own files. It fixes the `c07-rent-disagrees` line.
5. **The 31 deferred minors.** Before C06, only the items that touch data safety or honesty are done, as `safety-polish`:
   - a refused Bin still closes the hash question;
   - disagreeing answers;
   - the KEEP_CHANGED wording;
   - any other item the coordinator ranks the same way.

   The held-pile quota refund stays with `rate-limits` (P4-E). Cosmetic minors stay on the polish list until the freeze.

**Addendum, 2026-10-08: the P4-20b check of `ask-answer-loop`.**
1. **An answer that waits behind an active run.** The owner chose (A), at once, so "the next run applies it" means the end of the active run starts the waiting answer's scoped run. It does not mean the next tidy-up the person happens to press. Admission already records when a run ends: at that point the person object admits one scoped run for the answers waiting, under the quota and idempotently. The copy says "Bower will do this as soon as the current tidy-up ends", and a test proves it: an answer given during a run, then that run ends, and the scoped run starts without a press. The fix round builds this, not a rewording.
2. **"Write it": option (a).** `state-yes-writes` (`bower-escalated`) is built before the C05 deploy, so staging never offers a button that does nothing. The live answer for keep-one-note exercises the same path.

**Addendum 2, 2026-10-08: Home's full read.** The Inbox already shows within 0.6 s on the latency fake (`home-inbox-first`), and the full read finishes in the background. So 2 s for the full read is not what the person waits on.
- **Accepted:** `home-cache-stable` at about 4 s on the latency fake. The test is named for what it checks, "within 35% of the call minimum", with a golden of at most 46 calls. A test whose name says 2 s while it checks something else is not accepted.
- **The real risk is growth.** One load reads 20 dispositions, 12 changes and 7 digests, and those grow with every run, so after a year of use Home would read hundreds.
  - `home-reads-bounded` (`bower-implementer`), option (a): the runner stamps each disposition and change with its pile id in `appProperties`. Home lists only those for the piles in the inbox now, through a Drive query on `appProperties` ([Drive API, search files](https://developers.google.com/workspace/drive/api/guides/search-files)).
  - Test: Home's calls stay the same when the folder holds 10 or 500 earlier runs.
- **Option (b),** a device cache, is not adopted. It adds device state and sign-out handling for a gain that (a) already gives.
