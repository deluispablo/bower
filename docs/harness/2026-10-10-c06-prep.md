## Checkable parts of the promise

1. **Useful relation:** the reader can tell why two notes belong together from explicit evidence or the person's words; a shared word or co-arrival alone is insufficient.
2. **Across stored material and projects:** a new input can connect to an already stored note in another project, without requiring both sources to arrive together.
3. **Traceable claims:** each new factual claim has the right citation on that line; a generated source note leads onward to the actual filed source, without invented facts or web addresses.
4. **Correct identity:** the link reaches the intended note or file, including duplicate titles, path-qualified links and names changed during filing; mere existence is insufficient.
5. **Durable, bounded additions:** preserve personal prose and old history, avoid redundant source notes for confirmations and duplicate links/news on replay, and remain honest when needed context is not shown.

Items 1–2 require semantic review as well as structural assertions. Item 5 shares preservation/replay with C05 and missing-context handling with C15; C06 verifies its connection/citation effects without deciding those capabilities' policy.

## Open product questions for the lead and designer

These five questions remain undecided here; no owner question is sent from this preparation.

1. What minimum observable explanation makes a relation meaningful: a labelled link in prose, a sourced Timeline statement, or both? How does the person discover its reason in the app?
2. Must a justified cross-project relation be written in both existing hubs, or is the new source note linking both plus one hub update sufficient? The case 1 draft proposes both, subject to review.
3. When duplicate note titles exist, should authored links always show a project qualifier or only when ambiguous? Is the current file-opening behaviour sufficient to expose which identity a citation reaches?
4. Should a file that only confirms a known fact cite the raw filed text directly, as cases 2/3 propose, or should there be a source-note chain anyway? The draft reuses the current value gate and does not override it.
5. When a useful related note is outside the shown context, should Bower omit the relation, explain the limit, or request bounded more context? Does the prompt's 1–5 related-note requirement allow zero when no genuine related note is available? Coordinate the answer with C15 and the designer; do not add links to meet a quota.

Person-note permissions are governed by the later C05 ruling, not an additional open question here. These C06 proposals wait for that implementation if the eventual slice extends coverage to personal notes.
