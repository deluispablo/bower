# Technical-lead decision TL-P4-41: the B1 contract (index, folding, changes feed, two-step selection)

These are the rulings on the 11 questions in Codex's B1 preparation draft (p4-b1-prep ff1d684c, `2026-10-10-b1-prep.md`). The draft is accepted as the base, with its five-way split: B1a, B1b, B1c, B1d and B1e. It follows TL-P4-39 and its addenda, and the owner's principle of designing for normal use with one general mechanism and no special cases.

**What needs the owner's OK (TL-P4-40 (3)).**
- **No OK needed: the content of notes Bower writes.** Its MOC sections and index lines follow the owner's own vault templates (Overview, Notes, Sources; `- [[Note]] — summary`), so it is not app UI.
- **No OK needed: run-report rows that already exist.** These are "Updated …" and "Filed …".
- **Owner's OK needed:** new app UI, new report kinds, question copy and the question piece, all of which go through the designer, as with Q1.

## Rulings

- **Q1. MOC regions.**
  - A MOC that Bower creates is Bower's note (`type: moc`, Bower's mark). It has three new region kinds in ownership-format.ts:
    - `moc-overview`, written by the model;
    - `moc-figures`, written by a script;
    - `moc-members`, written by a script.
  - Each region has its own mark, and old notes stay readable.
  - A MOC or hub without Bower's mark (the person's) is never edited. Only the existing link-rewrite applies to it (TL-P4-32 addendum 1).
  - The new regions have no personal-edit handling (TL-P4-39 addendum 2). Current state keeps its existing protections.
  - B1 only folds hierarchies that already exist. Creating a hierarchy (splitting at 40) is B1e, gated until B5 and B6 define the type row's split criterion and templates.
- **Q2. Step 1's closed selection reply.** It has the shape `{ items: [{ itemId, kind, destination, wants }], asks }`:
  - `kind` is a type-row id or `unknown`;
  - `destination` is an existing folder id, or `{ parentId, name }` for a new subfolder;
  - `wants` is at most 5 note ids per source.
  - Selection is model-assisted from a candidate list that a script builds: index ids, the neighbourhood, and the folded MOC ids. The model can name only ids from that list, never paths or new ids.
  - Step 2's allowed targets are exactly the chosen ids, the destination folder, and that folder's hub or MOC.
  - A words-only pile counts as a source. Pinned answer and pair notes count within its 5.
  - When the model asks for a folded MOC, the runner shows its member list once (one expansion per step, within the budget), through the same retrieval path.
- **Q3. Prefix reads.**
  - The prefix is 4,096 bytes, read with `alt=media` and `Range: bytes=0-4095`.
  - If Drive ignores Range and answers 200 with the whole file, the adapter reads it and cuts at 4,096 bytes. Notes are small, and that cost is accepted.
  - A cut inside a UTF-8 character drops back to the last whole character.
  - Front matter that is incomplete within the prefix gives `(no summary)`.
  - Google Docs and other exports are not notes and are not indexed.
  - The fake covers 206, 200-full, 416 and empty responses. No live probe is needed, because both paths are correct.
- **Q4. One retrieval-state artifact.**
  - `.bower/retrieval.json` is versioned. It holds, by file id, the path, version, summary and coverage, plus the folder id, the account and the changes cursor.
  - `index.md` is a projection that can be rebuilt from it.
  - Both join RUNNER_WRITES explicitly.
  - The cursor is written in the same artifact as the state that reflects it, as one write, so the two can never disagree. The app never writes either file (hard rule).
- **Q5. Maintenance.** It is one deterministic `maintain` effect in the manifest, with declared inputs. It is evaluated from the settled outcomes after the other effects and before the report barrier.
  - It is idempotent: derived files are rebuilt whole and log lines are keyed by op id.
  - It never adds rows for refused effects.
  - It runs on every run, including answer runs and runs with no items, whenever the feed has changes or effects settled.
  - A run that is already done does not re-run it.
- **Q6. Overview rewrite.**
  - The Overview is rewritten when its MOC has gained or lost at least 5 members since the last rewrite. This is the same gate as About me (TL-P4-39 addendum 2).
  - It is rebuilt from the member notes' summaries plus the current Overview, never from itself alone.
  - The previous Overview is archived first in `.bower/archive/moc/<file id>/<date>.md`.
  - Folding is allowed before any Overview exists.
  - The 40 counts direct member notes, not subfolders.
  - When a group is still over 40 after a split, it splits again, down to a depth of 3. Beyond that, its figures say "list cut" honestly. Singleton groups stay as they are.
- **Q7. Budgets, as starting values measured on the corpus and tuned later.**
  - The index in context is at most about 8,000 tokens (32,000 characters).
  - The existing bounds stay: 24,000 characters of note text, 48,000 characters of source text, and at most 5 notes per source.
  - Maintenance makes at most 300 Drive calls per run.
  - 20% of the run's time is kept for retries, maintenance and the report.
- **Q8. Index order and format.**
  - Top folders come in PARA order (Projects, Areas, Resources, Archive), then subfolders alphabetically. A folder's direct notes come before its subfolders.
  - A duplicate title shows its shortest unambiguous path.
  - A folded line counts its members recursively: "→ [[MOC]] (312)".
  - Ids and versions are kept only in retrieval.json.
  - When the budget cuts the index, the context says so ("index cut: N folders omitted"), and no-match in a cut index never authorises creating a destination.
  - A missing index or state is rebuilt before planning. There is no fallback to the old 12 hubs.
- **Q9.** B1 implements no part of the large-request split. That belongs to B12 and Q1. B1 only must not break their later contract.
- **Q10. The changes feed.**
  - An id the cached tree does not know is resolved by reading its `parents` up to the Bower folder, to decide whether it is in scope.
  - If more than 50 ids are unknown, a bounded full listing runs instead.
  - The start token is taken before the bootstrap listing. Pages are drained to `newStartPageToken`, which is committed only with the refreshed state (Q4).
  - Only My Drive is supported; shared drives are documented as unsupported.
  - The state is bound to the folder id and the account.
  - Nothing repairs renames made outside Bower (TL-P4-39 addendum 2).
- **Q11. What the person sees.**
  - Maintenance of `index.md`, retrieval.json, hot and the log is hidden: no report rows.
  - A MOC created or updated by a run appears in the existing report rows ("Updated <MOC>"), only when it was actually written.
  - Undo rebuilds every derived artifact from the restored evidence at the end of the undo run.
  - No new report kind and no new UI, so no owner OK is needed. Visible questions belong to Q1.

## Order

1. **B1a, the contract (escalated):** regions, retrieval.json, the `maintain` effect and the selection reply.
2. **B1b, the ports:** Range and the changes feed, with fake parity.
3. **B1c, the index and folding of existing hierarchies.**
4. **B1d, two-step selection and the neighbourhood.**
5. **B1e, hierarchy creation,** gated until B5 and B6.

Cases 1-4 are accepted. Proposed cases 5-9 are added in their entries, and case 10 waits with B1e. Each entry follows TL-P4-29: a red from a Codex red session, the implementation, a Codex pass, and a fresh Claude review.
