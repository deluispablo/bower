# Technical-lead decision TL-P2-2026-10-06-31: Remove bins a pile's declaration copies

Lead: Claude `Planificador`. This answers the ratification request from `loose-pile-declaration`. It amends TL-P2-03 and TL-P2-06, which say that only a disposition retires a declaration.

## Ruling: option (ii), one rule for every pile

When the person removes a pile, Bower sends to the Bin, recoverably and never hard-deleted:

- the pile's folder, if it has one;
- **every copy of its declaration**.

Undo restores both. A declaration copy found in the Bin is ignored, and its skip is logged once. This applies to loose files and folder piles alike.

**Why.**

- **The person's explicit Remove is the retirement.** It is the same intent as a person-bin disposition. The difference is that it acts on the records themselves, so it needs no Bin evidence for a folder that may never have existed, as with a loose file that never arrived.
- **It is the usual soft-delete pattern.** Deleting an item moves it and its own records to the trash together, and restoring brings them back together ([Google Drive: trash and restore](https://support.google.com/drive/answer/2375102)).
- **One rule, not two.** No pile reappears after Remove on any device.

Disposition-based retirement for runs stays as it is. This adds the person's Remove as a second, explicit way to end a declaration. TL-P2-30 still governs folders moved or deleted outside Bower, and this ruling does not revive `declared-pile-folder-lost`.

## Left for later entries

- **A second device and a loose file.** The device sees "Choose X again on this device to send it." but cannot act, because choosing again needs a folder. Register a small entry for loose-file reselection under D02. The Inbox action must open the place where the person can choose the file (TL-P2-27).
- **Differing copies of a loose declaration** are only logged, where folder piles show the "two different lists" reason. Register a small consistency entry so loose piles show that reason too.

**Amendment (same day): a pile whose declarations are all gone is an ordinary pile.** This is option (b) from the loose-pile delta review.

**The rule.** When every copy of a pile's declaration is missing or in the Bin, the Inbox and the run both treat the pile as an ordinary observed pile, without a declaration. Both use the shared accounting, so they agree.

**What it covers.**

- **A pile restored from Drive's Bin after Remove** works again, as Drive's own trash and restore lead the person to expect. The Remove dialog promises exactly that.
- **A declared folder whose declarations were deleted outside Bower,** and an arrived loose file whose declarations are all in the Bin, stop showing a Try again that can never succeed.

**The cost.** Such a pile loses its declared-member guarantees: the run files what is actually there. This is rare and honest.

**What still holds.** A declaration that exists but cannot be read or is damaged is still held, under TL-P2-08 (a).

An in-app Undo on the Remove toast is not required, because it would not cover a restore made in Drive itself.

Registering `remove-bins-declarations` as its own entry, with a verify that removing a declared pile bins its declaration copies too, is agreed.
