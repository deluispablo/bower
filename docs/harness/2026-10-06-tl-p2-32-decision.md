# Technical-lead decision TL-P2-2026-10-06-32: the last legacy reasons from b-dest, and report wording

Lead: Claude `Planificador`. This answers the questions from lane b-dest (`b-path-destinations` and `b-path-generated-note`).

1. **The last two legacy reasons. Register both entries, with these rules.**
   - **`b-path-context-restore`: the runner never writes into the Inbox, so TL-P2-17 stands.** Restoring a declared pile's missing context note is the app's job. TL-P2-08 (b) says the app writes it again from the declaration's `originalText`. Until the note is back, the runner treats the pile as held, under TL-P2-21: it does not capture it, it adds no report row, and the Inbox shows the reason. The entry moves the restore into the app, if it is still in the runner, and removes the legacy reason.
   - **`b-path-pile-notes-only`: a pile of notes only is an ordinary note pile.**
     - The first pile note is its context (TL-P2-21), and B files that text as a generated note, with `create-text` and TL-P2-17's destination rule. This is what legacy does for a pile of words.
     - The other pile notes are uncaptured children, so the folder and those notes stay for the next run, under the late-child rule.
     - A pile with neither things nor text is item 4.
2. **Report rows use the file name, for now.** Bower's display rules already derive the shown name from the file name, and most names look the same. Capturing a separate `shownName` would change the contract for a cosmetic difference. Revisit only if the evaluation finds it confusing.
3. **One `setAside` row per item, at most.**
   - **If the move is rejected,** the only row is "It couldn't be filed this time.", because a missing note means nothing when the item was not filed.
   - **If the move applied but the item's note was not written,** the item keeps its `filed` row plus one `setAside` row: "Bower couldn't write its note this time." That replaces "Bower did not write a note for it.": it says what happened and implies the next tidy-up can try again.
4. **Confirmed.** On B, a pile with no things and no words is left untouched, and no file is written for it. It is consistent with TL-P2-21 and TL-P2-22: the Inbox shows "Nothing is left in it. Remove it from your inbox." with Remove.

No external standard applies; all four points are internal to contract B and its copy.
