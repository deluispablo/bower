## runner-network-retry (bower-escalated; TL-P3-28 point 2)

In C16, Actions run 37664576426 hit `TypeError: fetch failed` (ECONNRESET) in `RunnerToken.grant`, called from `RunnerDrive.stillCurrent`, `batch` and `runOperations`, while saving. The runner printed "It will try again." and "ended saving", and the job ended **success**. The person saw "saving" for 33 minutes until the Worker's alarm redispatched it as attempt 2, which then finished cleanly.

- **Read:**
  - `runner/src/main.ts` (about lines 260–295, the return code);
  - `runner/src/token.ts`, `runner/src/drive.ts`, `runner/src/status.ts` and `runner/src/effects.ts` (the read-back reconcile, as `lost-reply-reconcile` does it in the app);
  - `runner/src/spine/run.ts`;
  - [Google Cloud retry strategy](https://cloud.google.com/storage/docs/retry-strategy) (exponential backoff with jitter; retry only idempotent calls).
- **Fix:**
  - **Idempotent calls retry.** The token grant, the status report and Drive reads (list, get, `alt=media`) retry at most 3 times on a network error, 429 or 5xx, with exponential backoff and full jitter. Keep the total wait bounded (well under a minute) and say what it is. Never retry 4xx answers such as 401 `signed-out` or 409 `stale-attempt`.
    - The status report is idempotent by its revision and seq (a repeat is a 200 or a 409 `stale-report`). Say why.
  - **Drive writes never retry blindly.** A network error on a create, update or move goes through the read-back reconcile: read the target back; if the write landed, count it, otherwise it is not done. Reuse the existing reconcile, don't write a second one.
  - **Non-zero exit.** An attempt that ends without a terminal report (`done` or `failed` accepted by the Worker) exits non-zero, so the job shows failed. The Worker's alarm recovery still redispatches it.
  - The terminal-report rule must not change a run that already reported `done` and then fails a cleanup step. Say what happens there.
- **Named tests (runner):**
  - `a network error on an idempotent runner call is retried with backoff`. Use a fake fetch that fails twice and then answers, with timers faked and no real sleeps. Also assert that a fourth failure gives up.
  - `a network error on a Drive write is reconciled by read-back, never retried blindly`. Cover both a write that landed and one that did not. Exactly one write request is sent.
  - `an attempt that ends without a terminal report exits non-zero`, through `main`'s return code.
- **Extra gates:** the runner suite in full, and `runner/test/dispositions.test.ts` and the recovery tests unchanged and green.
- **Scope:** `runner/src/**` and its tests. `rules-repair-existing-folder` may land first in `runner/src/spine/run.ts`; rebase on the commit in your prompt.
