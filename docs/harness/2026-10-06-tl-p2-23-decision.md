# Technical-lead decision TL-P2-2026-10-06-23: the journal on the B path, and empty pile copy

Lead: Claude `Planificador`. This answers the questions from `b-path-journal` and the Inbox lane. Adopted revision stays `2026-10-05-contracts-2`.

## Journal on the B path

1. **`yourChanges` on B: accepted.** This replaces TL-P2-16 §6 on this point. It is present when it is grounded: the count of distinct archived records that are not requests or rules, per B. It is omitted when the count is 0. The app already shows nothing for an absent value or 0, so legacy's explicit 0 and B's absence read the same.
2. **Request-only runs with scope `instructions` on B: accepted.** No hashes are written, as on legacy. The B phases and wording are the intended experience. Fake e2e expectations change with it.
3. **Bad journal records and runner files.**
   - **Map them to `b-path-unreadable-runner-files`.** That covers an unreadable journal record, copies of one id with different bytes, a record with more than one parent, and a malformed `questions.json`.
   - **Journal records are the person's changes, so Bower never replaces or discards them.** A run on the B path leaves such a record uncaptured and unarchived. It logs one `BowerError` and goes on with the rest. Copies of one id that differ are all left in place.
   - **A malformed `questions.json`** follows TL-P2-17: it is Bower's file, so it is replaced.
   - **A Drive read error while planning** rejects before admission, as TL-P2-17 says.
4. **More than 20 requests: no new entry and no legacy reason.** A run captures at most the 20 oldest request records. The rest stay in the journal for the next run. So `requests.json`, which keeps the last 20, always grounds the report. This goes into `b-path-journal`.
