## Findings that change the spec or the plan

1. **d-v2-04 is not a TidySheet bug; it is the Sheet.** `ui/Sheet.tsx:30` passes `onCloseAutoFocus={focusMain}`. Radix 1.1.23's modal content prevents the default and focuses `triggerRef`, which is null because no sheet has a `Dialog.Trigger` (`node_modules/@radix-ui/react-dialog/dist/index.mjs:154-157`). So every `Sheet` sends focus to `#main`: TidySheet, ConfirmBin, NameSheet, MovePicker, Settings' delete, FolderScreen's New note and Explorer's two sheets. The fix has one site, `Sheet.tsx`, and it is `c4-focus-return` by definition.
2. **d-v2-02 Undo has no port, and the copy is wrong for three outcomes.** `VaultSource.answer` returns `void` (`data/sources.ts:88`). A yes about a pair, a state or an inbox thing starts a run at once (`data/answer-loop.ts:34-40,68-85`), with the outcomes `now`, `waits` and `failed` (`:53-57`). "Bower does it in the next tidy-up." is true only for `next`, and an Undo after a run has started cannot be honest. The lead needs a designer ruling: copy for `now`, `waits` and `failed`, and whether Undo is offered there.
3. **d-v2-08's "now" is not the code.** `--line-strong` does not exist anywhere in `src/`. Today every field has its own CSS in seven modules, with an inset `--line` ring (about 1.2:1) or none. There is no shared field in `src/ui/`, so "one field rule" is a new home.
4. **d-v2-13's `.skeleton` is dead CSS.** No element uses `ui.module.css:134` `.skeleton`. The real loaders, Home's `.skel` and the folder's `.skel`, are already still. The red cannot be reproduced for the skeleton. The pulsing `.live` (`tidy.module.css:50`) and step `.mark` (`:22`) are real. `.rbBusy` (`app/shell.module.css:35`) and `.paper`, `.prop`, `.pc`, `.folderProp` and `.ground` in `tidy.module.css:2-14` are also unused.
5. **d-v2-07: the engine lacks half the "existing ranges".** The blink is 1.6 to 5.2 s, not 2.4 to 5.6 (`bird/engine.ts:615`). The engine has no preen, no sleep, no startle and no gaze from focus or touch. Gaze follows the pointer only over the layer's parent (`bird/Bower.tsx:156-165`). Poses exist only as CSS keyframes (`bird/poses.css`).
6. **Today the run chip's mini Bower probably takes the turn from the page's Bower.** Presence makes the newest bird of the top priority the mover (`bird/presence.ts:18-24`). `RunChip` mounts after `<Outlet/>` (`app/PhoneShell.tsx:34-37`) at priority 0. Verified in the code, not at runtime. d-v2-07 needs birds that never take the turn.
7. **d-v2-21 "See all … opens the Inbox folder" has no destination.** `/files/Inbox` redirects to a pile or to Home (`features/files/FolderScreen.tsx:39,43-47`). The designer has to name the target.
8. **d-v2-22 Settings "You" already exists** as "Account": the name, the address and Sign out (`features/settings/Settings.tsx:176-191`). The block is a move and a rename, not a new section.
9. **The axe checks the spec relies on are off today.** In axe-core 4.13, `target-size` is `enabled:false`, and `heading-order` and `landmark-one-main` are best-practice rules of moderate impact. The sweep in `e2e/app.spec.ts:97-104` keeps only serious and critical results and disables `region`. Each block's accept test must name its rules. The Playwright phone project is a Pixel 7, 412 px wide (`playwright.config.ts:14`), so 375×812 tests set their own viewport.
10. **In-flight overlap.** The `c3-pair-ask` round 2 worktree (`/private/tmp/bower-c3-pair2`, uncommitted) edits `features/tidy/RunLinks.tsx` and `features/note/NoteScreen.tsx`, and adds an `AnsweredRows` component for run-report rows. d-v2-11 and d-v2-20 touch `RunLinks`, d-v2-07 touches `NoteScreen`, and d-v2-02's local confirmation row must not become a second "answered row" component (see d-v2-02).
