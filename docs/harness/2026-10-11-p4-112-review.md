Minor:
1. `type-table.json` cannot be created the first time: write-runner-json needs an existing `before` file and create-text is
   refused, while `readTypeTable(null)` says `writeAllowed: true`. B5b must define creation (barrier seed, as hashes.json).
2. `readTypeTable` of `{v:1,rows:[]}` or all-invalid rows gives an empty table (not the seeds) with `writeAllowed: true`; rows
   with an unknown extra key are skipped, so a later rewrite would drop them. Decide in B5b.
3. Currency set comes from `Intl.supportedValuesOf` (ICU), so app and runner could disagree on an obscure code; a fixed
   ISO 4217 list would be deterministic. `propertyValuesOk` is not yet on a live path.
4. `profile-rewrite` does not require `byBower` as `moc-rewrite` does; the profile mark alone is the authority. Safe now.
5. `typeRowOk` bounds neither the number of properties nor the number of rows.
