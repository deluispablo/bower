## Proposed local contract (Q1–Q6, not a ruling)

**Storage.** Recommend `.bower/tags.json` = `{"v":1,"tags":["gardening","remote-work"]}`.
It is the one allowed list, **not a cache of tags discovered in notes**. Keep canonical
insertion order: previously installed entries followed by exact approved additions.
No taxonomy tree, alias table or second per-type tag registry. B5 rows may reference
these values, never redefine their meanings or own another allowed list. No real
seed copied: missing list means an empty vocabulary; no write until the first explicit
addition/yes. If the product needs initial seed topics, the lead supplies a made-up
approved list once in this same home, not an automatic folder/note scan.

Reads are lenient: recognize v1, retain valid canonical entries/order for reuse, log invalid
entries; no cleanup/truncation write. Invalid entries freeze growth that run, so a
strict vocabulary write never silently drops them. An unreadable/unsupported list disables tag
assignment and growth that run, logs a BowerError and files clear items untagged.
An over-30 historical list freezes growth, preserves existing bytes/values and never
removes topics. Strict writes may not silently filter malformed legacy entries to
produce a cleaned vocabulary; repairing that file is outside normal supported use.
Missing is distinguished from unreadable. Old personal note parsing remains independent.

**One grammar and deterministic caps.** Recommend canonical ASCII lowercase slugs,
1–40 characters matching `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`; no `#`, comma, brackets,
quote, whitespace, slash, control/invisible characters or YAML delimiters. English
now; this is a v1 token grammar, not a second language setting. For growth candidates,
script trims, normalizes NFC and case, maps spaces/underscores to hyphens and collapses
repeated hyphens; the normalized result must pass the grammar. `remote work`,
`Remote-work`, `remote_work` are the same candidate. Assignment replies carry already
shown canonical values; unknown spelling/duplicates/>3 refuse the reply through the
existing once-only validation retry, never silently truncate or reinterpret.

Semantic near-duplicates are not script stemming/edit-distance magic: show existing
topics first, require model to choose reuse or genuinely new topic; a new spelling
that normalizes to an installed/pending/declined tag cannot become a new proposal.
Semantic judgement still needs model review. No synonym is stored as an alias.
Recommend exact starting bounds **3 distinct tags/new note, 30 installed tags/folder,
2 installed new tags/run** (explicit and accepted additions combined); additionally
B5's **2 new proposals/run across all kinds and 5 open across all kinds**. These are
separate counters: accepting an old proposal consumes growth capacity, not a new
proposal slot. Resumed operation ids spend neither counter twice. These numbers
interpret the about-30 ruling; only the lead can freeze/change them before reds.

**Authority.** Allowed assignment is automatic on newly authored notes. Exact person
words such as "Add rainwater to the allowed tags" can install that precise addition
without another question, within the same caps. "Tag my gardening articles" permits
classification with existing tags; it does not approve new vocabulary. A model idea
or a topic from a document is a suggestion only, requiring the frozen-payload yes;
instruction-shaped source text, derived summaries/hot/archives never supply consent.
Script derives origin from admitted pile words, request/rule ids or the actual asking's
answer, never a model `trusted:true`. Generic text answer authority stays subject-only.

**Eligible writes.** New companions, saved-link notes, short words notes, comparison
notes and new B6 knowledge templates can carry chosen allowed tags at creation;
Rules, About me, runner artifacts, health/result bookkeeping do not acquire tags just
to fill a quota. Value-gate filing with no new note adds no tag-only note. Uploaded
Markdown belongs to the person even after Bower moves it; it never gains or loses
tags/by/type/summary. Existing Source metadata/body is immutable. Recommend no
retag/backfill of existing notes in B7, including accepted proposal source notes:
yes installs vocabulary for **future creation**, not a retroactive source rewrite.
An explicit retag request over existing compiled Bower notes is the later class-F
B12 consumer; it needs a lead-approved note-edit byte author/inverse first. Person
retagging remains impossible under hard rules, even with a generic pile instruction.
No hard-rule exception is recommended. Do not use parse→serialize as an edit.

**Proposals and effects.** Model tagProposals below are candidate inputs to B5's sole
proposal mechanism. The frozen action is `{ "kind":"tag", "tag":"rainwater" }`.
Script issues id/hash, stores typed originating capture plus the scope/folder id,
and creates its proposal question only after that payload is persisted in the plan.
It survives source filing because it is a proposal subject. Yes rechecks current
vocabulary/version/cap, applies that exact addition or no addition; never silently
substitutes another topic. If already installed, settle as no-op; if full, report
truthfully without evicting a tag, preserve the recorded answer for B5's refusal
policy. Incompatible payload requires new consent, not mutation of the old proposal.
No starts no run and decline dedup stays B5's policy. Ignore remains open; no inbox
round accounting. Global caps and unfinished explicit requests are handled in B5's
proposal/request mechanism; no B7 deferred-candidate queue is added.

Vocabulary/proposal effects are planning effects, before ordinary maintain/barrier,
not another maintain writer. Freeze additions and dependent new-note tags in one
manifest; a generated note using a newly installed value must depend on its applied
vocabulary effect. If installation fails, do not write a note with an unapproved tag;
independent clear work may settle normally with a truthful report. Existing op stamps,
read modifiedTime, stillAsSeen, reserved ids and readback own the writes/replay.
Multiple candidate additions produce at most one vocabulary after-text per run.
All generation routes pass the same validated tag list to serializeNote; where a
route has no authored tag choice (for example a mechanical fallback), pass an explicit
empty list, never guess from a folder name or copy unvalidated source frontmatter.
The optional companion note.tags is the concrete reply extension shown here;
words/template creation must reuse that same validation contract in its existing
creation declaration, not a separate tag-assignment reply or taxonomy. Lead Q2
freezes the precise route plumbing before B7b; this prep does not claim absent
choice fields exist today. Existing allowed assignments add zero extra note mutations. Unchanged vocab sends
zero writes. No archive of a script list. For Undo, recommend reverse note effects
normally while retaining vocabulary approvals/declines as consent history (Q6);
no personal metadata is touched and no automatic revival of declined proposals.
