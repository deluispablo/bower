## Proposed mechanism contracts, pending the questions below

**One log format home: `src/data/contracts/log-format.ts` (new).** Keep the appendix's
four-field line. Date is the frozen admission UTC day; action is a closed enum; note is
a JSON string containing the actual settled path; detail is a closed JSON object:
`{v:1,key,runId,operationId,fileId,from,to,detail}`. `key` is SHA-256 of canonical
`[rootId,runId,operationId]`, not a name, message or attempted timestamp. Use existing
canonical JSON/hash functions, escaping every literal pipe inside JSON as `\u007c`.
JSON handles quotes/backslash/CR/LF; prohibit actual CR/LF in encoded fields. Splitting
on ` | ` then decoding must reproduce all original field values. `# Log` and the
`> Format: bower-log/1; year: YYYY.` header identify the generated format.

Suggested operation mapping: generated note create → create; ordinary note edit → update
(link-only repair → fix); captured inbox filing move → ingest; other visible move/rename
→ move; settled Bin → move with destination Bin; an approved B7 tag-list decision →
decision using B7's actual op evidence. One event per op, not both ingest and move.
Exclude hidden journal archives, report/checkpoint/cache writes, all derived maintain
writes (including health), and no-op effects. A rejected update has no update event;
its existing report refusal still stands. Frozen outcome hashes/ids, not report prose,
are the event inputs. Log is audit evidence, never authority to grant new changes.

**Bounded active log and lossless sealing.** Recommend at most **512 KiB UTF-8 / 1024
events** per active or sealed segment and at most **4096 bytes** per encoded event.
The fixture's 1024 events occupy **378578 bytes**, so it exercises the event bound
without already violating the byte bound. If adding the next whole event exceeds
either cap, or its admission year changes, first seal the exact active bytes by a
reserved create, confirm the checksum, then replace active with the next segment.
First seal for a year is `.bower/log/2026.md`; subsequent same-year seals use
`.bower/log/2026-<first event key>.md`. Paths are selected from declared archive metadata
and frozen with reserved ids before sends, never by a replay's fresh name choice.
Multiple small segments in one run are permitted within the shared budget. Empty
segments are not sealed. No archive scan on replay; the frozen ids and write-once
evidence reconcile exactly the affected segments. Never delete older years or truncate
events to satisfy the bound. Total retained history grows, but each rewritten/read
segment and each run's work are bounded. Annual rotation alone is insufficient.
Oversized legacy data stays untouched until a bounded lossless seal can be authorized;
an unparseable/torn log stops its replacement with a logged BowerError, not an empty
fallback. Old unencoded lines remain conservatively readable; no guessed field split
is used for dedup and no current run claims complete legacy decoding. Q2 rules migration.

**One lint reducer: `runner/src/lint.ts` (new, pure).** Inputs come from B1's id/version
listing and the existing read cache, plus actually settled writes. Extend retrieval's
same per-file cache with optional lint evidence: hash/version, parsed links/tags,
summary/type/status, meaningful Timeline date and parse/coverage state. No second
lint index or persistent queue. Snapshot changes are captured before manifest persistence;
overlay primary after-texts only for applied create/edit outcomes and drop vanished/Bin
targets using B1's rule. Consume B5/B7/B11 reader diagnostics through their accepted
codecs rather than revalidating their schemas with a lint-specific implementation.

Findings have stable `(kind,fileId,target-or-key)` identity, evidence versions, severity,
and enough source references to link the person to the exact note. Sort deterministically
by kind and unambiguous path. Missing personal metadata is advisory; no autogenerated
full metadata requirement on a personal note. A non-hub orphan requires a **complete**
incoming-edge graph, excluding health itself, hidden files and Inbox; self links do
not establish incoming references. Resolve real paths/titles by VaultIndex identity;
ambiguous targets produce ambiguity, never an arbitrary match. Ignore fenced code with
the shared fence transition, preserve alias/#heading/^block semantics via linkTarget.
Use original bindings, not attachment title substrings, for unlinked-original checks.
For stale active projects use last valid Timeline activity (60 days); no activity means
unknown, not modifiedTime or an invented creation date. Duplicate names use raw Drive
names and ids before VaultIndex display disambiguation; duplicate summaries compare
decoded nonempty summaries. Do not use duplicate findings to merge automatically.

**Bower health uses existing note/edit/report mechanisms.** Recommend visible root
`Bower health.md`, with normal B2 summary and `by: bower`, empty personal payload and
diagnostic Markdown in `## Bower's note`. Root placement matches Rules/About me and
keeps this diagnostic out of the subject-note graph. Create with serializeNote and
ordinary reserved generated creation; replace only the existing Bower-owned span with
note-edit's new narrowly bound health-rewrite, preserving every other byte. The target
file id and ownership are declared by script. If a personal note already has that title,
do not adopt it or create a name-numbered duplicate; Q6 rules the honest failure path.
The health note includes checked/unchecked counts and never says the folder is healthy
when coverage is incomplete. A broken target appears as text/code; only existing source
notes are actual wikilinks. Findings describe facts and options in note content, never
claim a repair was made or place filenames/jargon in app error sentences.

**One recovery and report boundary.** B8 extends the handed-off maintain declaration
with bounded log-before bytes, diagnostic snapshots/reader diagnostics, health target
identity/version, missing-target reserved ids and rollover targets. All text is
deterministically derivable from those frozen inputs and immutable primary outcomes.
Before each mutation, use the same version/fence/write-once checks as an ordinary effect.
Archive confirmation precedes active-log replacement; health and other projections
must be confirmed before maintain's commit is considered complete. Preserve B1's
retrieval commit semantics, extending its receipt/readback to bind every required
artifact, rather than moving retrieval early and treating its stamp as sufficient.

Recommend one additive **maintenance receipt inside the applied checkpoint evidence**,
validated in run-checkpoint: maintain op id, artifact paths/ids, content hashes/evidence,
and `created|updated|unchanged` dispositions derived from the frozen preimage. A resumed
write that already landed retains its original created/updated disposition. The receipt
does not appear as a new public report field or live in a new file/store. materialize
consumes only its confirmed actual health create/update and produces today's row;
fixedReport and the canonical report barrier serialize that same row. Unchanged health
produces no row. Other entries' maintain results use this receipt too, if their handed-off
contracts already provide one; do not add a parallel B8 receipt mechanism. Q5 must settle
the additive shape and legacy validation before code is written.
