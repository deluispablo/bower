## Evidence boundaries

No network research or live model call was made. The local standard is the existing intent interface and its validation, not a new contradiction writer. The spec describes a contradiction callout (`docs/specs/2026-10-04-who-does-what.md:35`), but that conceptual operation is not a reply key: the strict envelope accepts only things, notes, lines, states, asks and keep (`runner/src/claude.ts:800`). Adding `contradiction`, multiple `cites`, certainty metadata, or a generic resolution ask to these objects would fail the existing format. No such extension is proposed as already authorized.

The existing prompt says to give both figures and cite the new thing when it disagrees with a note (`runner/src/claude.ts:273`). Timeline lines cannot contain links and have a single scalar citation (`runner/src/claude.ts:815`, `:833`, `:913`); Bower adds that source link. A source note's authored body can link actual existing originals and the original being filed (`runner/src/claude.ts:308`, `:984`). The exact proposals below use that body to put both original links together, plus one Timeline line on the stored note. This is a testable representation within today's interface, offered for review; it does not settle where the final C07 callout belongs in the UI.

Notes are shown with bounded text: at most 12 notes, 4,000 characters per note, and 24,000 across notes (`runner/src/claude.ts:157`, `:414`, `:420`). Selection includes Bower-owned notes and hubs (`runner/src/claude.ts:411`); stored original text files are not automatically supplied as note bodies. The first three cases therefore summarize the old source's claim in a shown, Bower-owned note and also retain its original file. They test detection from that shown record, not fresh rereading of the old original. Both original texts are available to the independent quality reviewer. Truncated, unshown and person-authored context needs separate coverage; do not claim exhaustive conflict search.

Number grounding checks occurrence, not which source asserts a claim, its effective period, or whether it is tentative (`runner/src/claude.ts:672`, `:848`). Valid JSON and grounded numbers cannot establish semantic detection. The scorer checks substrings, dated Timeline content/counts, file preservation, report lists and resolved links (`runner/src/corpus.ts:258`, `:269`, `:276`). Its links resolve by any matching path or basename (`runner/src/corpus.ts:229`); `linksResolve` only checks changed notes. Separate Timeline substrings can occur on different lines (`runner/src/corpus.ts:272`). The proposed exact body string makes both source links observable for these uniquely named fixtures, but does not provide a general claim-to-source or stable-id assertion.

C05's accepted harness gaps are partly closed: exact question counts and typed merge pair subjects exist (`runner/src/corpus.ts:78`, `:300`), and `between` supports edits or moves across two calls (`runner/src/corpus.ts:37`, `:62`; `runner/test/corpus-run.ts:138`). The driver reads deterministic replies through the existing Claude provider, admission and production runner (`runner/test/corpus-run.ts:133`, `:166`, `:178`), binds `$file:NAME` by exact admitted name (`:204`), and can run another press on the same Drive (`:158`). Do not request a second lifecycle driver or write path. The additive `between` format has no answer-generated-question or add-new-input step; a future lifecycle test can orchestrate those using the existing driver after the lead rules.

All three new folders are `covers: model`: exact scripted objects are prepared below, but no outcome has been run through that boundary in this assignment. No `replies.json` is added and no new outcome is claimed scripted. The requested corpus command loads all cases and checks numerical grounding, but executes/scorers only the scripted set (`runner/test/corpus.test.ts:12`, `:29`, `:171`). This distinction follows `harness/corpus/README.md:10`.

## Scripted proposal preparation

Each block is the exact intended reply object at the existing intent boundary, not a direct file edit. `$file:NAME` is the existing driver's binding notation: substitute the exact admitted fileId before validating the object (`runner/test/corpus-run.ts:214`). Never emit the placeholder to the production planner or match an id by substring. Optional arrays are omitted. Source-note prose describes the incoming source alone, as the existing prompt requires (`runner/src/claude.ts:263`); the Timeline supplies the comparison against the shown old record. Source-note bodies contain the two original links; Timeline `text` contains no link, and scalar `cites` supplies only the incoming original. Both amounts/dates are grounded by the admitted source and the shown note. No fabricated id, stamp, certainty field or mutation operation is returned.

No `asks` proposal is used to smuggle in a resolution question. An existing `asks` pair means “keep one note”, and a file/pile ask leaves its subject unfiled (`runner/src/claude.ts:939`, `:955`). Neither is a generic contradiction decision. A state proposal can trigger an ownership permission question (`runner/src/claude.ts:275`), which likewise must not be confused with choosing the factually correct source. The top two expectations bound questions at one but do not require a question or settlement. Whether a contradiction needs its own typed decision is an open product question, not a schema change in this preparation.

## Open product questions for the lead and designer

Five questions; these are not decided by the fixtures or asked of the owner by this worker.

1. Where should the disagreement appear: the stored note, a source note, Home, or a combination, and must both originals be reachable together from that callout? The exact replies demonstrate today's source-note-plus-Timeline representation only.
2. When does an unresolved contradiction need a question, and what does each answer mean? Should the person select a claim, acknowledge uncertainty, or leave it open? A no must not automatically certify the older source; existing merge/file asks cannot stand in for this policy.
3. What permits resolution without asking: explicit supersession for the same period, effective dates, source authority, or the person's rule? Is document recency alone ever sufficient? The new same-period case deliberately does not choose a winner.
4. How should possible disagreements, conditions, unread evidence and omitted context be worded and surfaced? What threshold makes a risk worthy of a Home question, and how is limited coverage made visible without invented confidence scores?
5. After a resolution, what changes Current state and how does new evidence reopen it while preserving the two claims and the person's edits? Which explicitly named person-authored notes may C07 inspect or append to under the narrow C05 authorization?
