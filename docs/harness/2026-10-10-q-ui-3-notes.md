## Test first

The new e2e file was written before the CSS fix. Exact red names:

- `q-ui-3: tall desktop sheet stays inside the window and scrolls (demo)`
- `q-ui-3: tall desktop sheet stays inside the window and scrolls (fake)`

Both use 1280×720. From an empty Home, add 24 text-only piles through
Inbox → Add a pile → What is this? → Put the note in the inbox. The made-up
content is `Garden idea 1` through `Garden idea 24`. Stay within the app
between additions so demo's in-memory piles survive. Open the existing
tidy-up confirmation sheet via Home's `Tidy up 24 things` button; do not start a run.
There is no test-only product hook or injected content.

The positive control checks all 24 names and requires the pile list itself
to exceed 720 px. The regression assertion requires the sheet's bounding-box
bottom to be at most 720 px and its top to be nonnegative. The scrolling checks
require scrollHeight > 720, scrollHeight > clientHeight, overflowY = auto,
actual positive scrollTop after scrolling, and Not now inside the viewport.
The open dialog is scanned using the existing expectAxeClean helper with
wcag22: true, which enables WCAG 2.2 AA and target-size.

Red and green e2e were not run: the owner states ports are unavailable.
The expected original failure is `the sheet ends inside the viewport`;
no observed failing or passing browser assertion is claimed.

## Fix and standard approach

Only the desktop `.sheet` rule gains
`max-height: calc(100dvh - 12vh - 24px)`.
Reuse the original shared sheet's `overflow: auto` rather than introduce a
second scroll mechanism. The phone rule is unchanged.

Standard CSS references (links supplied without network access):
- https://developer.mozilla.org/en-US/docs/Web/CSS/max-height
- https://developer.mozilla.org/en-US/docs/Web/CSS/overflow
