## Contract

1. **Index bytes (Q8).** `.bower/index.md` is rebuilt whole from retrieval.json as a projection.
   - Order: PARA top folders (Projects, Areas, Resources, Archive), then subfolders alphabetically; a folder's direct notes come before its subfolders.
   - A note line is `- [[Note]] — summary`. A duplicate title shows its shortest unambiguous path.
   - A folded line is `→ [[MOC]] (N)`, where N counts members recursively.
   - Ids and versions live only in retrieval.json.
   - Past the budget the index says "index cut: N folders omitted".
   - Hidden paths never appear.
   - It is written only when more than its date changed; a no-change run writes nothing.
2. **Folding existing hierarchies (Q1, Q6).**
   - A folder that already has a Bower MOC folds into one line.
   - The MOC's `moc-members` and `moc-figures` regions are script-rebuilt from state by id, with complete membership and no duplicates.
   - The 40 counts direct member notes, not subfolders.
   - A person's MOC or hub is never edited (link rewrite only).
   - No hierarchy creation: that is B1e.
3. **Budgets (Q7).** The index in context is at most about 32,000 characters. Maintenance stays within 300 Drive calls per run and adds no re-reads of same-version files (B1a's read cache).
4. **Lifecycle.**
   - All of this goes through B1a's single `maintain` effect, inside the manifest, before the report barrier, idempotent on replay.
   - A missing index or state is rebuilt before planning, with no fallback to the old 12 hubs.
   - Goldens rise only by named calls, each pinned with its reason (TL-P4-41 addendum 4 pattern).
