## Property

`src/bird/settle-blend.test.tsx`: **the moves-off settle blends the whole drawn output to the still frame**.

One property definition, partitioned into 684 independently executed cells:
19 REACTIONS kinds × 18 starts × witness/random batches. Starts come from all
nine POSE_REFERENCE poses and all seven ACT_REFERENCE acts, plus an already
turned idle and a layer. Preen starts 0.6 s into its act; land starts 0.05 s in.
The turned witness focuses behind Bower for 1.5 s before disabling moves.
The done witness starts one second into the display; error/offline witnesses
start 1.5 s into their reaction, covering the sleep/alarm handover.

Every cell uses seed 240726. Random batches allow two generated runs; witness
batches allow one explicit example and one generated run. `endOnFailure` bounds
the work without changing the test timeout. Random timings include the moment
before the first settle frame and the last frame before release (0..35 frames).
Pose destinations and injected mind acts range over their complete fixtures.

Three deterministic replays drive the actual mounted engine and preference:

- Control: the original motion, then `usePrefs.birdMoves = false`.
- Foreign: the same start, plus chirp, a mind act and a changed gaze target during settlement.
- Pose: the same start, plus a rerender to a different pose at a generated settle moment.

Layer cells use the control and foreign tracks; layers have no pose prop to
rerender. Pose changes are exercised for every fixture pose/act/reaction cell.
Both ordinary and Settings still frames belong to the random property's domain.
No assertion reads `motion`, springs, channel ownership, head velocity, `busy`,
`asleep`, or any other engine flag. The public release spy marks the lifecycle
boundary and reads the DOM immediately before the real release clears it.

The reader measures every part's angle, translations and both scales, both iris
coordinates, the rig, bird/perch translation and facing scale, dimensions,
opacity, carry-chip output and glyph visibility. It reads attributes and inline
styles while animated and actual still-frame CSS after release. jsdom does not
load Vitest's CSS imports, so the test loads the existing CSS locally; it also
accounts for jsdom not resolving SVG display presentation attributes in CSSOM.

The static reference is a rendered minor PoseBower with the existing still
stylesheet. Settings' head/eye overrides and the ordinary moves-off open eyes
follow the packet. The continuous blend oracle uses the specified cubic
0.6 s ease-out and apply()'s decimal drawing precision. The tolerance is 0.005
per scalar times max(1, abs(reference)), preserving a bound at zero. Glyph
display is categorical: checked at release and handover, not numerically eased.

Clauses: (a) original still frame at release, including a queued-pose track;
(b) the next frame after release equals the release drawing in the control and
foreign tracks; (c) foreign tracks equal the uninterrupted control, including
synchronous calls, and the control follows the whole drawn blend (layer
breathing included); (d) the pending pose cannot alter any pre-release frame,
and its still frame must be present after release. The deliberate pending-pose
change is checked separately from (b)'s uninterrupted handover: it may occur
only after release and is not mistaken for an unintended release jump.
