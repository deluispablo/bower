## Proposed closed language and evaluation semantics (for Q1/Q2)

One declaration contract in `src/data/contracts/view-format.ts` (new) is shared by the
reply validator, stored declaration reader and manifest validation. One pure evaluator
in `runner/src/views.ts` (new) consumes typed values from B5, with no Drive or Claude port.
The engine owns I/O; the evaluator is new functionality, not another writer or parser.

- Version/id/kind are fixed: `v:1`, slug `id`, `aggregate` or `formula`. Unknown keys
  or operators refuse on write; unknown/invalid historical view is skipped on read with
  an honest unavailable result/B8 diagnostic, never executed as text. Reject keys such
  as `__proto__`, technical keys and output overwrites of raw declared properties.
- Aggregate set: known row `type`, scoped `folderId`, explicit `recursive` boolean,
  optional typed `where`. Predicates: eq/ne, lt/lte/gt/gte for compatible scalars,
  contains for a list element, in for ≤10 literals, exists, all/any/not. Missing or
  invalid operands evaluate unknown, including ne/not, never select a row by accident;
  `exists` can explicitly select missing presence. Track unknown-filter exclusions.
- Group keys: declared scalar property, or ISO date bucket. Weeks start Monday (ISO
  week-year), month/quarter/year are calendar buckets. Missing group is `Other` with
  its count, not lost. No model taxonomy; output stable by group keys, currency, then
  measure order. Top ties use code-point order, stable file id breaks row-order ties.
- `count` counts selected unique notes; `countValues` counts valid values, flattening
  lists with duplicate values once per note; `top` counts distinct notes per list
  value and returns ≤20 rows. Do not infer values from note prose or summaries.
  Scalar sum/average/median/min/max/range require numbers or same-currency money;
  earliest/latest/date range require dates. Range returns endpoints (not an implicit
  subtraction); median averages the middle two finite values. Money partition is
  implicit even when not declared in groupBy. No exchange-rate lookup or mixing.
- Missing (absent/null/blank) and invalid (wrong type/date/currency/nonfinite) values
  are unavailable, excluded and counted separately per measure. Empty count is 0;
  empty sum/average/median/min/max/date result is unavailable, never a misleading 0.
  `if` evaluates only its chosen branch, but both branches must statically typecheck;
  unknown condition yields unavailable. Division by zero/overflow yields unavailable
  with a reason; do not serialize Infinity, NaN, or invent an area/amount.
- Date property is a real ISO date, date-only arithmetic in UTC whole calendar days;
  reject impossible dates. `dateDiff(left,right)` means left minus right; daysUntil
  is date minus persisted run as-of day, including zero today and negative overdue.
  Timestamp/local-zone input needs an explicit future typed conversion, no implicit
  host timezone. Money +/− is same currency, money/number is money, money/money is
  dimensionless only with equal currencies. Reject money×money and money+number.
  Plain numbers do not magically supply square metres: trusted request binds area
  to that unit for this view's label, not a global inferred schema alteration.
- Formulas reference only raw declared input keys plus admitted constants/as-of.
  ALL computed keys are excluded, even acyclic chains; never feed a stored previous
  `days_left`/`price_per_area` into another formula. Output type must match declared
  property type/label; raw input key collision refuses. Case 3 seeds an installed-formula specimen in the row, with its output keys marked
  computedBy; a stale prior output is replaced
  or removed when unavailable, with the missing/invalid reason in MOC figures when
  that view has a MOC result, otherwise B8's existing health-note consumer later.
- Proposed caps: ≤4 KiB UTF-8 per declaration; ≤32 AST nodes, depth ≤8, ≤4 group
  keys, ≤8 measures/outputs, ≤10 views per home; bounded text/list/enum values stay
  TL-P4-47's 200/10/20. Count filter/formula children in the same AST cap. These are
  **new starting limits for the lead**, not a change to any red or existing budget.
  Native finite number arithmetic; deterministic rounding for rendered output only,
  retaining raw finite result. Monetary display uses B5's existing Intl policy;
  v1 does not promise exact accounting cents for arbitrary decimal arithmetic.

No scheduler or notification is implied by daysUntil. A new run refreshes dates; a
closed browser/no-run day creates no new Home prompt. Time questions in class J need
an explicitly consented threshold and Q1/B3 consumer; they cannot be fabricated from
any negative output. Outside grammar: one B12 map if budget/permissions allow, otherwise
an honest reason plus nearest alternative, never model-authored executable code.
