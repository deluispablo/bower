1. **Row contract.** What is the stored Markdown row grammar, match language and precedence

   How should malformed, edited or over-budget tables fail/report without guessing?
2. **ESCALATED — contracts and one-write-path hard rule.** Which existing manifest effect
   will safely create/update Bower-owned Markdown in `.bower`, with bytes/modifiedTime
   fences and strict-write/lenient-read validation? Its current JSON write path is not a
   Markdown API. Rule on the minimal contract change; never a direct write at run end.
3. **ESCALATED — question contracts.** How does the existing question carry the exact
   proposed row and stable identity after the source is already filed? Current inbox asks
   cannot also file and then survive subject closure. Which subject/payload is authorized,
   how does the real answer loop schedule its acceptance, and how is it checked on replay?
4. **Proposal lifecycle.** Does “at most 2 per run” cap new distinct proposals, all shown
   pending rows, or report rows? Specify candidate ordering, excess handling, decline vs
   ignore retention/re-asking, and the old type-proposals report field's reconciliation with
   hot/Open threads. No extra acceptance UI or second store is assumed.
5. **ESCALATED — personal-data/ownership hard rules.** What if a named profile is missing,
   moved, duplicated or person-authored? Who may create one, and how is its stable identity
   retained? May sensitive profile facts come from a CV/certificate, or does B4's own-words
   limit also govern profile notes? CV synchronization never grants adoption of personal prose.
6. **ESCALATED — note-edit bounds.** Where does the roughly 400-word profile live while
   C05 states are at most 8 × 200 characters? Does it remain a short Current state with
   sourced detail elsewhere, or is a lead-approved contract extension required? Do not
   raise these bounds or add a profile-specific writer inside B5.
7. **ESCALATED — note contracts and Bower-section hard rule.** Approve the template home,
   section ownership, full front matter and Source-body immutability alongside C05's
   owned sections. How do existing Project Next steps and certificate inventory updates
   pass the existing update path? Must MOC/Source also have the generic generated Timeline?
   What represents an absent url, and does a hub count toward 1–5 related notes when no
   other relevant note exists? The fourth case's template names remain draft conventions.
8. **Reuse contract.** What makes a near-duplicate name the same project/area/topic (case,
   punctuation, singular/plural, Unicode, synonyms)? How is an existing tag used as a fit
   before B7 exists, and does that still require a folder/MOC? No arbitrary edit-distance
   bound, semantic library or second tag list is chosen here.
9. **Project evidence.** May a clear goal/end date in admitted words or source justify a new
   Project? `newPlace` currently accepts only a shown note or Rules line as its basis;
   B6 cannot faithfully demonstrate that create branch merely by copying a pile into basis.
   Resolve the validator contract before that new Project fixture becomes a red.
10. **Dependency/context contract.** Confirm how B5 inserts the table after B1–B3 and how
    a row's profile enters the five-note-per-source candidate budget. The ruling says hot
    first in B3 but gives About me then hot in its context-order list; B4 follows B5/B6.
    Which order/absence behavior should their shared context test assert before B4 lands?
