- **Acceptance contract:**
  - **One provider interface** in `src/data/spine/`: what a run plans from the admitted set it took.
  - **The scripted provider.**
    - It is `planRun`'s planning extracted over a read port (`spine/read.ts`), not a copy.
    - `fake-runner.ts` calls it and keeps its behaviour: its tests and `pnpm e2e:fake` stay green.
    - It is deterministic: the same folder and admitted set give the same plan. It uses no model and no network beyond Drive reads through the port.
  - **Real effects.**
    - `runner/src/main.ts` picks the scripted provider by an environment variable (default scripted; anything unknown refuses to start with a clear error).
    - It builds the real Drive effects on the `runner-drive-adapter` `FencedDrive`: each operation's send and evidence read go through the adapter's fenced writes, with still-as-seen and the attempt check.
    - Injected effects stay only in tests. A run on Actions therefore really changes the folder (C12).
    - The test drives `main` against Drive v3 faked over fetch (`runner/test/drive-v3.ts`) and the Worker faked over fetch, and checks the folder after the run.
  - **The workflow:** `runner/workflows/tidy.yml`. It is not under `.github/workflows/`, because the bower-app backup must never run Actions.
    - It runs on `repository_dispatch` of type `bower-tidy`.
    - Its `run-name` is `tidy <run_id> <attempt>`, which the Worker's recovery looks up.
    - It uses Node 24 and runs the built `runner/dist/runner.mjs`, with the dispatch payload and `BOWER_API_URL` (a repository variable) in its environment.
    - It needs no secret, has `permissions: {}` (or the least it needs), and never echoes the ticket.
  - **`scripts/new-instance.sh`**, adapted from the original:
    - It copies only the built runner bundle and `tidy.yml` into the instance repository, removes the original app's workflows in the same commit, and sets the `BOWER_API_URL` variable.
    - It never asks for, reads, prints or sets a secret (the Claude credential moves to P4).
    - It keeps the original's safety: changes only when something changed, plain bash 3.2, `gh` and `git` only.
    - The lead runs it, never a worker. Its test runs it against a local bare repository with `gh` stubbed on `PATH` and asserts the committed tree.
