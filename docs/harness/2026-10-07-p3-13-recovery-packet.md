- **Acceptance contract:**
  - **Resume from the chain.**
    - Attempt 2 reads only `.bower/runs/<run_id>/`, verifies the chain, and skips applied operations.
    - A `possible-effect` is reconciled by reading it back before anything else (landed, not landed, unreadable). One that landed is never resent. One not landed may be sent once, under attempt 2's fence. One unreadable stops the run without a resend.
    - Journal lines are archived once, and `dispositions.json` stays the same as an uninterrupted run's.
  - **The old attempt is fenced.**
    - After attempt 2 takes over, attempt 1 is woken. Its next fenced write, attempt check or status report is refused, through the adapter's attempt check and the Worker's `stale-attempt` 409 (TL-P3-18).
    - It changes nothing in the folder and nothing in the Worker's run.
  - **A fault at every step.**
    - For each checkpoint the chain can hold (the first one, each outcome state, "effects done, report pending", and done), kill the attempt right after that checkpoint is written, then resume as attempt 2.
    - The final Drive state (names, parents, trashed, content hashes) and the report must equal those of an uninterrupted run of the same plan.
    - Run the test twice: once on the fake, and once on the adapter contract test (Drive v3 faked over fetch, `runner/test/drive-v3.ts`).
  - **No app call.** The runner and the faked Worker alone complete the run in the runner tests.
  - **Named tests, red first:**
