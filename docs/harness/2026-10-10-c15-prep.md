## C15 promise split into checkable parts

1. Consume a valid app-prepared package for the captured ready set; bind evidence and candidates to the admitted identities and current source versions, never to a name guess or a later arrival.
2. Revalidate content/version, extraction version/configuration and account/folder scope before reuse; cache is acceleration, never authority for an effect. Preserve compatible old inputs.
3. Reconstruct absent or unusable preparation from the current sources deterministically, including external additions and a closed originating browser, with the same evidence and bounds as the prepared route.
4. Bound initial reads, extraction, candidate count and model text; mark cuts, unread pages and unavailable text. Missing content must not be presented as read evidence.
5. Request additional evidence only through a bounded context mechanism, separate from Home questions and invalid-reply retries; stop on exhaustion, repetition or no progress, and reject out-of-scope identities.
6. Finish with grounded proposals and an honest limited outcome: file when fit is established, ask when genuinely unclear, continue unrelated ready work, and never invent missing facts or bypass mutation fences.
7. Measure cold/warm preparation, reuse, reads, context and exchange counts so boundedness and equivalent meaning can be tested; fingerprints compare model inputs, not cache validity or write authority.

Parts 1–3 derive from the preparation contract and architecture above; parts 4–7 separate the promised bounded mechanism from quality and cost evidence (`docs/P2_ACCEPTANCE.md:59–61`). Product choices about extraction kinds and exact limits remain open below.
