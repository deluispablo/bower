## Transport permissions and guards

Use separate A and B DriveHttp objects, separate tagged fetch closures and independent observer O, sharing the same already validated grant and aggregate budget. A and B must not share memoized file metadata/content. Shared credential refresh serialization is acceptable: this tests interleaving under one identity, **not different-account, different-client-ID or appProperties project isolation**.

The new guard admits only these exact operations on `https://www.googleapis.com`, with no redirects, userinfo, fragments, credential query strings or unrestricted parameters:

1. One `POST /drive/v3/files`, `fields` exactly current FIELDS: JSON **one folder**, exact synthetic name/unique probe marker, parent exactly provider alias `root`. Provider root is a creation parent only; **no GET/list/search/update/Bin on provider root**. No existing root lookup or personal content discovery. A durable private create-intent is recorded before the first send; successful returned ID alone establishes `R1_ROOT` for later operations. Never retry this logical root-create request automatically.
2. One `POST /upload/drive/v3/files`, exactly `uploadType=multipart` and current FIELDS: exact synthetic `fixture.md`, sole parent `R1_ROOT`, exact probe marker, text/markdown and exact BASE bytes below. Parse the actual generated multipart boundary/content privately to validate semantics and bounded length; do not require a fixed random boundary or log the body. Immediately register the returned ID as `R1_FILE`. No resumable initiation/URI, arbitrary upload, replacement creation or child outside that root.
3. Metadata GET of privately allowlisted `R1_ROOT`/`R1_FILE` with exactly current FIELDS; content GET only `R1_FILE` with exactly `alt=media`. Optional diagnostic metadata `fields` explicitly adding `version` is separately named and counted; it is not needed for the first race and never becomes an input precondition. No export, fullText or unscoped listing.
4. Media PATCH only `R1_FILE`, exactly `uploadType=media` and current FIELDS, content-type text/markdown, and actor-specific exact B or A payload. Each actor's PATCH admits one actual forward after its final precheck. No injected If-Match in the first case, parent/name/mark updates or extra content writes.
5. Cleanup metadata PATCH only privately registered IDs, exactly current FIELDS and JSON `{trashed:true}`, after the ownership reads below. One exact synthetic-root parent listing solely for cleanup inventory may be admitted: `('R1_ROOT_ID' in parents) and trashed = false`, fixed small pageSize/fields, no OR/search/fullText, no following unknown page token. A second page or unknown child means cleanup boundary failure; do not Bin the root automatically. No DELETE/untrash.
6. OAuth transport only the reviewed tokenProvider's exact existing-client refresh POST to its fixed token endpoint, privately validated form fields; no authorization-code exchange, new consent, cert-key fetch, scope expansion or revocation in this case. Use the injectable `tokenProvider(config,f,now)` transport so refresh attempts share the same counter/deadline. No direct bypass fetch.

Before **each actual dispatch**, including read retry/refresh and A after barrier release: validate exact private config/grant/resource identity binding, strict approved Boolean and current authorization expiry; check aggregate request/byte/time/operation bounds and the allowed ID/parent/payload. Maintain owner-only private directory 0700 and manifest/artifacts 0600, outside both source repositories and public packet/evidence paths. Persist created IDs, marker, actual parent, create intent and cleanup state atomically before admitting the next operation; forbid symlink/public destinations. Public reports contain aliases only.

The adapter obtains its token before entering the fetch shim (`drive-http.ts:226–233`). Therefore the queued A bearer may age at the barrier. On actual release, validate authority again and verify the queued bearer is still the same validated, unexpired grant using private state; otherwise stop before forwarding. Do not silently swap identity or replay A. Keeping the barrier short reduces risk but does not replace the dispatch-time check. Reviewed tokenProvider already validates saved-session binding and exact scope at use/refresh (`oauth-local.mjs:118–147`); it does not expose expiry through its public closure, so this check needs a reviewed **root-only private-state guard**, not a guessed token lifetime or public token inspector.

Request/response body sizes count across attempts; stream-bound replies rather than trusting Content-Length. Fixed 20-second upstream timeout per dispatch plus aggregate monotonic deadline, matching current auth wall-clock expiry. No automatic probe restart or client retry. DriveHttp normally retries some 429/403/5xx (`drive-http.ts:241–253`); the shim must count each request and refuse a second forward of a mutation. For a non-2xx/uncertain write, stop the case and reconcile only the known synthetic file under remaining authority. Throw a fixed-message shim error: the unchanged adapter maps it to its readable unknown error, and reviewed safeConsole suppresses raw diagnostic arguments. Do not require an unexported isolated BowerError class or change the loader. Record the original upstream status privately/sanitized separately; this fault policy is not evidence about native production retry behavior. Only the unmodified, successful-forward race supports/refutes the existing precheck strategy.

Capture genuine upstream **response** header values privately with bounded length before reconstructing any response, preserving exact validators if present. Never persist request Authorization headers, tokens, token response bodies or resumable URIs; resumable routes are refused entirely here. Do not log raw response headers/Location/URLs/IDs/body/exception strings. Passing the actual response body/status/necessary headers back to the adapter must preserve its normal semantics; instrumentation must not inject validators, fabricate a 2xx, change payloads or move the barrier after dispatch. Sanitized public telemetry: actor/resource alias, fixed operation alias, upstream status, monotonic timing, byte count/hash, barrier events and Boolean assertions. Header presence may be reported as a Boolean, never as a claim of supported conditional semantics.

## Literal data and smallest execution

Exact UTF-8/ASCII fixture bytes, including final LF:

```text
BASE = "user: base\ncompiled: base\n"
B    = "user: external\ncompiled: base\n"
A    = "user: base\ncompiled: app\n"
```

These are opaque synthetic strings, not a proposed ownership grammar. Compute BASE/B/A SHA-256 from those literal bytes before execution, not from the observed final output. The hashes are safe evidence; real IDs, filenames/markers used for binding, raw metadata/headers remain private.

1. Root preflight: validate current packet, source/public-module hashes, grant/account/client/scope correspondence and private manifest permissions. Confirm no prior root-create attempt exists for this case; if resuming, use the existing manifest and never create another root. Start aggregate counters/deadline. Root validated callback grant is the starting fact; provider access remains unobserved until the following real requests.
2. `A.createFolder('root', exactSyntheticName, exactProbeMark)` once. On completed successful response, persist returned `R1_ROOT`; read its metadata and assert own marker/name/provider-root parent. `A.createText(R1_ROOT,'fixture.md',BASE,exactProbeMark)` once. Persist returned `R1_FILE`; independently get metadata and read content, assert expected parent/marker/name and BASE hash. If create response is missing/ambiguous, stop without blind recreation or personal root search; cleanup may remain incomplete.
3. A reads file metadata and content independently; assert BASE hash and keep that exact modifiedTime, `m0`. Prepare literal A bytes before any interleave. Start `A.writeText(R1_FILE,A,m0)`.
4. Its final upstream metadata GET must actually complete and return `m0`; the immutable adapter must pass its equality check. The actor-A fetch shim then receives the prepared PATCH and **pauses before forwarding it**. Record `A_precheck_complete` and `A_patch_waiting`; no A PATCH has reached upstream yet. A rejected precheck is a different stale-read case, not this race.
5. Only after the barrier, B independently gets current metadata and calls `B.writeText(R1_FILE,B,mB)` (this supplies B's own final precheck). Its one actual media PATCH must complete with a successful upstream response. Observer O independently gets metadata and reads content; require B's exact hash and same fixture parent/name. Record `B_write_upstream_complete` and `B_observed`. An unconfirmed B edit is not a counterexample and must not release A.
6. Release A only after those facts, rechecking dispatch authority/bounds/token state. Forward **the unchanged queued A request**. Record dispatch and genuine upstream completion/status before delivering the reply. O independently reads metadata and content afterward; no cached response or caller result substitutes for provider post-state. Save hashes, statuses and ordered timings; private metadata identifies actual versions.
7. Decide the assertion below, stop further experiments on the first lost update, and perform only allowed fixture cleanup. Even a safe case leaves structural, conditional and lost-response cases untested; no full R1/P2 acceptance.

Primary assertion: **B's confirmed external edit survives, or A's stale write is refused without losing B.** Exact final B hash plus refusal supports that one observation; any proposed merged outcome must show B bytes preserved and be explained by actual provider response, not a fabricated local merge. Final exact A hash after confirmed B plus an actually forwarded A PATCH is a **lost-update counterexample: observed-refuted; STOP current strategy**. Any final bytes losing B's external contribution are likewise a counterexample. Do not perform a restoration write, call a later post-write check safety, or hide the overwritten edit behind cleanup. Unrelated/unknown content, timeout, failed B verification, missing barrier or unsuccessful bootstrap is **inconclusive**, with no safety claim. A precheck refusal before the B interleave is not proof that the gap is safe.

## Budget, failure recovery and cleanup

Hard aggregate envelope: **60 actual HTTP attempts including refresh, 10 minutes, 64 KiB aggregate request plus response body bytes**. Only tiny text fixture/multipart metadata/token refresh bodies; never expose those private refresh bytes. Any tighter current owner packet dominates. Bytes/time include failed attempts. Reserve at least 10 requests and the last two minutes for cleanup; do not begin further non-cleanup dispatch after request 50, minute 8, or insufficient remaining authorized time. No optional case automatically consumes this reservation.

| Baseline stage | Drive requests without retry |
| --- | ---: |
| Root creation + ownership metadata; file creation + metadata/content verification | 5 |
| A initial metadata/content + final precheck; B current metadata + final precheck/PATCH; independent B metadata/content; A PATCH; final metadata/content | 11 |
| Child ownership GET/Bin/trashed confirmation; root child inventory + ownership GET/Bin/trashed confirmation | 7 |
| Normal Drive total | 23 |

Allow at most two refresh requests, leaving 35 requests below the absolute ceiling for bounded read retries/reconciliation and any cleanup exception; this headroom is **not permission to add cases**. First source/grant/boundary mismatch, expired authorization, unconfirmed mutation, unexpected child or lost update stops normal dispatch. Already issued I/O is not cancelled/rolled back merely because authority expires. If authority expires after a write, record pending observation/cleanup and require a renewed same-resource packet; do not issue unauthorized recovery calls or revoke the account grant.

Keep creation state durable in the private manifest. No returned ID after unknown root-create outcome means no safe root discovery here: no broad query/recreate/Bin. Unknown child-create outcome permits only the already authorized synthetic-root cleanup inventory; an unknown child is recorded privately and blocks automatic root Bin until separately bounded ownership recovery. Process failure must reopen the same manifest, read known IDs under fresh authorization and reconcile actual effects; it never assumes a missing caller reply means the file was not created/written. Do not repurpose an unknown-ID response or unrelated object as the fixture.

Cleanup, with valid authority/budget: get `R1_FILE` immediately before Bin, compare its recorded ID/fixture marker/name and sole `R1_ROOT` parent; wrong/missing ownership or relocation means refuse cleanup and record residual aliases. Content may be A/B from this case, but unrelated bytes flag a residual rather than authorizing removal. Bin only that child, never DELETE. Confirm `trashed:true` through an allowlisted raw metadata read: `DriveHttp.get` intentionally rejects trashed objects, so its not-found error alone is not Bin confirmation. Inspect the one exact synthetic-root child listing for unexpected live children; then read root ownership/marker/name/provider-root parent immediately before Bin and Bin only the recorded root. Confirm its trashed flag privately. Read-before-Bin checks are bounded ownership checks, **not an atomic guard against an external concurrent move**; this controlled disposable fixture requires no uncoordinated actor after the case. Do not infer safe user-content deletion from it. Report `cleanup.completed` and remaining aliases independently of the experiment verdict; denied/missing/changed resources or cleanup bound exhaustion never become a green exit.

## Later cases and decision impact

No lost-response injection occurs in the first case. A future genuine lost-response case must first forward the request, receive/bound the real upstream response to completion privately and record that fact, then intentionally withhold delivery to its caller. Abort before forwarding is an unsent case; timeout after forwarding without upstream completion is **unknown effect**, not a confirmed lost response. Reconciliation reads known provider state before considering any further logical write; another B edit must survive. Response-headers-received alone is not complete reply delivery evidence.

A conditional candidate is a **separate optional packet**, only after root/lead decide the next step and a genuine observable validator exists. Preserve its exact private bytes from the same media/metadata route; first successful matching-validator control, then a confirmed B change and stale-validator negative control, with independent content reads proving refusal without mutation. A made-up validator, output-only version treated as an input parameter, ignored header, failing positive control or unsupported route is not evidence of compare-and-swap. Distinguish media and metadata semantics. If the first case loses B, stop the current strategy before any optional extension; further work is a remedy probe, not continuation under a passed premise.

If refuted, technical lead must select and specify a demonstrably safe remedy (supported conditional update with observed semantics, or immutable/append-only effects with explicit conflict reconciliation/product interaction). Post-write checks and app-local locks cannot recover already overwritten external bytes. Serialize any change to `DriveApi.writeText`, fake/real implementations, runner mechanics and downstream consumers; preserve stale-write refusal/user text and add literal compatibility/fault fixtures before dependent O3/O4 acceptance. Keep Worker small and deterministic mechanics shared; do not introduce a universal write proxy or parallel mutation engine by inference from this packet.
