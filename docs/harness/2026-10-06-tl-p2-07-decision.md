## D02 splits into two entries, in order

The new app has neither resumable upload nor IndexedDB, so keeping uploads across a reload is a new capability, not a small part of reselection. A reviewer could accept one half and reject the other, so they are two entries:

1. **`upload-queue-persistent`** (new, first). Adapt the original app's queue and resumable session: `app/src/upload-queue.ts` and `app/src/cache.ts:520–596`. The resumable protocol goes in `src/data/drive/`, the queue in `src/data/`. It must:
   - keep the selected bytes in IndexedDB until Drive confirms the complete file, then delete them;
   - resume the stored session offset after a reload, with a bounded restart when the session has expired;
   - let only one tab upload;
   - request persistent storage and check quota, and disclose a storage failure in one plain sentence;
   - key each member by declaration and member key, with the content hash;
   - reserve the file identity before creating it, following TL-P2-05's pre-generated-ID recommendation. A restarted session reuses that identity and confirms it by reading it back, so a member is never created twice.

   The fake Drive gets the matching behavior: resumable session, offset, expiry, reply lost after an effect, and a reserved ID refusing a second create. The real protocol stays P3/R4 evidence.
2. **`pile-member-reselection`** (D02, after the queue). This covers the case where the retained bytes are gone (storage refused, another device, cleared data). The person chooses the file again; it is accepted only if its hash matches the declared hash. Otherwise it is refused with a plain sentence, and the member stays missing and retryable.

**Sign-out and accounts (journey 9).** Pending uploads stay through a reload and a sign-out, like the journal outbox. They are keyed by account and folder. They resume only for that same account and folder. Another account never sees or sends them. Leaving Bower (`deleteAccount`) removes them. The person can discard a pending member the same way they remove one today.

**Tests.** Reuse the original tests' IndexedDB setup if it has one; otherwise add the maintained `fake-indexeddb` package as a development dependency rather than writing an IndexedDB double, and record that reason in the entry. Reused code keeps its provenance in the commit: the original repository, its path and FSL-1.1-MIT.
