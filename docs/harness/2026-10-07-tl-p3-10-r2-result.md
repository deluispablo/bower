# Technical-lead decision TL-P3-2026-10-07-10: the R2 result, and what follows

**R2 attempt 2, 2026-10-07:** steps 1–5 pass against staging with the owner's two test accounts. Separate folders; sign-out answers 401; each account's Drive token gets 404 on the other's folder; signing in again finds the same folder (`found: true`). Step 6 did not run, because the cookie is `HttpOnly`.

## Rulings

1. **Step 6 is covered by the Worker tests.** A replayed cookie after sign-out is refused because sign-out raises the session generation, and that is deterministic Worker code tested in `worker-google-oidc`. R-probes exist to test provider behaviour (Google, Drive, GitHub), not our own code. R2 passes.
2. **`found: false` on the first `POST /vault` is covered** by the `worker-vault-pointer` tests. Step 1 proved the real Drive side: the folder and its five main folders exist.
3. **The client must not retry a 404.** A missing `/status` route made the real bundle retry about 100 times. Retrying a client error never helps, so only network failures, 5xx and 429 are retried, with backoff ([Google Cloud retry strategy](https://cloud.google.com/storage/docs/retry-strategy)). This becomes the entry `client-retry-policy`, on `bower-implementer`, in the next batch. The `/status` route itself comes with `worker-status-revision`.
4. **The one `?signin=failed` during A's first sign-in** most likely came from the sign-in state cookie expiring while the chooser sat unseen in the hidden pane. Failing that way is the truthful behaviour. So that the next one can be read, enable Workers Logs (`"observability": { "enabled": true }` in `api/wrangler.jsonc`, free tier) ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). Pass the deploy SHA as `APP_VERSION` with `--var`, so `/health` names the build. Both go into the next batch as one `bower-mechanical` entry.
