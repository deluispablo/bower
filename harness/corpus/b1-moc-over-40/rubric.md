# A 41-item MOC folds without losing evidence
The parent Gardening map starts with 41 member links. Its already-present Soil and Water child maps contain 21 and 20 members, each linking the parent. Folding replaces the parent's flat list with its child-map links and exposes only the parent MOC row in the large-folder index. Every original clipping remains byte identical and reachable through exactly one child; Overview content is retained because no new primary evidence was admitted.
Expected names follow the existing seeded child maps, not a new naming algorithm. The folder contains 44 eligible notes (41 members and 3 maps); the 40 threshold counts members, not map files or rendered rows. No content is removed, summarized from its own summary, or moved into new personal folders.
The index substring checks need a stronger structure oracle: exact eligible count, one parent row, two child links, complete unique 21/20 membership, recursive reachability and no lost ids. No model call may generate lists, counts or the index. Input versions belong in the ruled derived-state contract, not a made-up fixture key.
This fixture proves reuse/folding of an existing hierarchy, not automatic creation of child maps or the B5 split-criterion schema. A separate proposed 40→41 case must prove that boundary after the lead rules on B5/B6 dependencies and writable MOC regions. Current legacy headings are format input only and grant no new writable region. Covers:model pending those contracts and scripted production proof.
